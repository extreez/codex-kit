# Веб-поиск/research MCP — советчик по выбору

Четыре конкурирующих MCP общего назначения для поиска и получения контента.
Не взаимозаменяемы полностью — разные акценты, поэтому не один победитель, а
выбор под конкретную потребность проекта. Для простого разового поиска уже
хватает встроенного `WebSearch`/`WebFetch` — ставить один из четырёх имеет
смысл, когда нужна конкретная фича из таблицы ниже.

## Кандидаты

| Инструмент | Лицензия | Ключ | Сильная сторона |
|---|---|---|---|
| **Firecrawl** | не указана явно (open-source) | нужен после лимита | JS-рендеринг, массовый краулинг, PDF/DOCX/XLSX-парсинг |
| **Exa** | не указана (open-source MCP) | нужен для полного API, MCP-режим бесплатен | Академический поиск (arXiv, Semantic Scholar), поиск по коду |
| **Tavily** | не указана (коммерческий) | нужен | Защита от prompt injection, структурированный research-эндпоинт, PII-фильтрация |
| **Apify** | MIT | нужен (или AGI/x402/Skyfire) | Тысячи готовых «акторов» под конкретные сайты (соцсети, карты, e-commerce) |

## Рекомендация

- Академическая тема, нужен arXiv/Semantic Scholar — **Exa**.
- Нужна защита от вредоносного контента на входе (агент читает недоверенные
  страницы) — **Tavily**.
- Нужен конкретный источник данных, под который уже есть готовый скрейпер
  (LinkedIn, Amazon, Google Maps) — **Apify**.
- Общий краулинг сайта целиком, включая JS-тяжёлые страницы — **Firecrawl**.

`research-deep` по умолчанию работает через обычный `WebSearch`/`WebFetch` —
любой из четырёх ставится как усилитель для конкретного проекта, не как
обязательная зависимость (та же логика, что платные SEO-API в `library/seo-*`
- опция, не включённая по умолчанию).
