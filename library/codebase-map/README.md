# Карта кодовой базы — советчик по выбору

Не кандидаты сами по себе — они реальные блоки в `blocks/` (`repowise`,
`socraticode`, `codegraph`, `graphify`, `understand-anything`). Этот файл
только помогает выбрать, какой ставить, до `/kit add`.

Задача одна на всех пятерых: дать агенту структуру и зависимости проекта
без чтения файла за файлом. Ставить больше одного в проекте смысла нет —
группа зафиксирована в `CONFLICTS.md`.

## Рекомендован: repowise

Даёт больше остальных: граф зависимостей, git-история, health-score,
мёртвый код. Измеренный эффект: -31.6% токенов агента, 3.8 вместо 7.2
вызовов инструментов на задачу. По умолчанию ставить его, если нет причины
иначе.

```
/kit add repowise
```

## Если нужен смысловой поиск сверх repowise

**socraticode** — единственный, кто не дублирует repowise целиком.
Гибридный поиск (семантика + ключевые слова), индексирует не только код:
схемы БД, API-спеки, инфра-конфиги.

```
/kit add socraticode
```

## Остальные — дублируют repowise без нового смысла

- **codegraph** — тот же граф зависимостей, без git-истории и health-score.
- **graphify** — статический экспорт (HTML/MD/JSON) для разового просмотра,
  не живой источник для агента на каждый запрос.
- **understand-anything** — дороже по токенам (LLM-анализ бизнес-логики),
  дашборд для человека в браузере, не под запросы агента.

Ставить один из этих трёх — только если у `repowise` конкретная причина не
подошла, назвать её.

## Установка

Все пять сами ставят себя при подключении — `.mcp.json` с `npx` (codegraph,
socraticode) не требует ручных действий, `repowise`/`graphify` ставят себя
через pip/uv при первом вызове скилла, `understand-anything` просит два
слэш-команды (агент их набрать не может — так устроены слэш-команды). Ручной
зависимости, кроме исходно нужных для проекта (Node, Python, Docker для
socraticode), нет.
