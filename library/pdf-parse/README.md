# PDF-парсинг — советчик по выбору

Новая ниша для codex-kit — ни один существующий блок не покрывает PDF→текст/
markdown со структурой (таблицы, координаты). `academic-research`/`fact-check`
читают PDF через обычный `Read`, если он текстовый; эти два инструмента нужны,
когда важна структура (bounding box цитаты, таблицы, сканы с OCR).

## Кандидаты

| Инструмент | Лицензия | Особенность |
|---|---|---|
| **liteparse_samples** (jerryjliu, LlamaIndex) | не указана | Демо PDF/DOCX/PPTX/XLSX-парсера с визуальными цитатами (bounding box — где именно на странице взята цитата) |
| **pdf-inspector** (firecrawl) | MIT | Rust, быстрый (<200мс на документ), классификация страниц, selective OCR (только там, где нужно, не весь документ подряд) |

## Рекомендация

**pdf-inspector** для чистой скорости и предсказуемой лицензии (MIT,
явно указана). **liteparse_samples** — если нужна именно визуальная привязка
цитаты к месту на странице (bounding box) для отчётов, где важно показать
«откуда именно взята цифра», а не только текст.

Оба — кандидаты, не встроены по умолчанию ни в `research-deep`, ни в
`fact-check`/`academic-research` (те работают через `Read` на текстовых PDF
без переносимой доп. зависимости). Ставить точечно, когда реального PDF со
сложной структурой в проекте много.
