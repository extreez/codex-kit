# Извлечение и публикация контента - советчик по выбору

Ничего из этого файла не установлено и не подключено - `.mcp.json` не
тронут. Это справочник на случай, если `seo-content`/`geo-content`/
`llms-txt` работают не только промптом, а реальным конвейером
извлечения/публикации контента.

Другой угол, чем `library/seo-crawler-tool` - тот про живые SEO-данные
(позиции, обход сайта на аудит), этот - про сам контент: забрать
структурированный текст со страницы или опубликовать готовый результат
в CMS со структурированными данными.

## Firecrawl (`firecrawl.dev`, репозиторий `firecrawl/firecrawl-workflows`)

MCP-сервер + API для краулинга и извлечения контента в чистом виде
(markdown/структурированные данные из HTML). `firecrawl-workflows` -
готовые промпт-воркфлоу поверх API, один из них прямо называется
«seo audits». Кандидат, если `seo-content`/`geo-content` нужно вытащить
контент конкурента или своего же сайта без ручного разбора HTML -
замена самодельному `curl`+парсингу. Требует API-ключ (платный после
бесплатного лимита).

Репозиторий: https://github.com/firecrawl/firecrawl-workflows

## Sanity agent-toolkit (`github.com/sanity-io/agent-toolkit`)

MCP-сервер для headless CMS Sanity: GROQ-запросы к контенту, схемы,
публикация, Content Releases. Среди agent skills пакета - прямо
названный «SEO/AEO optimization with structured data». Кандидат, если
проект уже хранит контент в Sanity и `seo-content`/`geo-content`
готовят текст, который нужно сразу опубликовать со структурированными
данными, а не просто выдать как markdown-черновик. Не подходит проектам
без Sanity - это не универсальный CMS-адаптер, а обвязка конкретно под
Sanity Content Lake.

Репозиторий: https://github.com/sanity-io/agent-toolkit

## Когда какой ставить

- Нужно вытащить и разобрать контент со страницы (своей или чужой) -
  `Firecrawl`.
- Проект хранит контент в Sanity, нужна публикация с готовыми
  структурированными данными - `Sanity agent-toolkit`.
- CMS не Sanity, или контент не в CMS вообще (просто файлы в репозитории) -
  ни один инструмент не подходит, публикация остаётся ручной или через
  штатный API конкретной CMS проекта, отдельно от этого блока.

## Как это соотносится с блоками

`seo-content`/`geo-content` готовят текст методологией без привязки к
источнику данных - без Firecrawl работают на том, что дал пользователь
или что доступно через `WebFetch`. `llms-txt` ссылается на `.md`-версии
страниц - если контент уже проходит через Sanity, генерация этих версий
может опираться на agent-toolkit вместо ручной подготовки.
