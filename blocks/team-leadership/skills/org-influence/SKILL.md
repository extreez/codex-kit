# Влияние в организации

5 инструментов из `Owl-Listener/design-leadership-skills`, изначально
под продвижение дизайн-функции, применимо к любой функции, которой
нужно влияние без формальной власти. Файлы в `templates/` дословно на
английском — текст говорит «design», при использовании для другой
функции читать как свою, атрибуция в начале каждого.

## Какой инструмент когда

| Запрос пользователя | Файл | Что даёт |
|---|---|---|
| «как продвигать ценность команды» | `templates/design-advocacy.md` | Показать результатом, не лозунгом; говорить на языке каждой функции; создавать спрос, не продавливать |
| «построй нарратив для руководства» | `templates/executive-narrative.md` | Начать с их цели, не своей → один сквозной посыл → запоминающийся артефакт/цифра → готовый ответ на возражение |
| «составь карту влияния» | `templates/influence-map.md` | Реальный decider (не номинальный) → кто на него влияет → позиция каждого → кого убеждать первым |
| «выстрой отношения с руководителем» | `templates/managing-up.md` | Понять их мир и метрики → без сюрпризов → приносить решения с опциями, не только проблемы |
| «выбей ресурсы на команду» | `templates/securing-resources.md` | Попасть в бюджетный цикл рано → привязать ask к профинансированному приоритету → опции good/better/best, не ультиматум |

## Как выбирать

`influence-map` — точка входа перед крупным решением (кого убеждать и
в каком порядке). `executive-narrative` и `managing-up` — по разным
адресатам: narrative — для аудитории, которую видишь редко (совет,
конференция), managing-up — для своего прямого руководителя постоянно.

`securing-resources` привязан к бюджетному циклу компании — не
запускать вне контекста планирования, эффект теряется, если прийти
после того, как аллокации уже закрыты.

Решения выигрываются до совещания, не на нём — источник прямо
предупреждает не загонять скептика с высоким статусом в публичный
угол, работать с возражениями заранее и приватно.
