# Стратегия функции

5 инструментов из `Owl-Listener/design-leadership-skills` (плагин
`design-strategy`), изначально под дизайн-лидерство, применимо к любой
функциональной организации (инженерия, продукт, данные). Файлы в
`templates/` дословно на английском — текст говорит «design», при
использовании для другой функции читать как свою, атрибуция в начале
каждого.

## Какой инструмент когда

| Запрос пользователя | Файл | Что даёт |
|---|---|---|
| «напиши стратегию функции» | `templates/design-strategy-doc.md` | Vision кратко → честный диагноз текущего состояния → несколько ставок → явный список «не делаем» → как поймём, что сработало |
| «сформулируй vision команды» | `templates/design-vision.md` | Будущее состояние конкретно, user-centred, амбициозно но правдоподобно, влияет на решения следующего квартала |
| «обоснуй инвестицию в команду» | `templates/investment-case.md` | Возможность/риск в бизнес-терминах → конкретный ask → ожидаемый возврат с диапазоном → цена бездействия → доказательства |
| «сформулируй принципы, которые решают споры» | `templates/org-design-principles.md` | Формат «X over Y» (принуждает к trade-off), не больше 7 штук, тест на реальных прошлых спорах |
| «расставь приоритеты между командами» | `templates/prioritisation-at-scale.md` | Каждый кандидат → к какой ставке/KR привязан, impact×confidence×effort, баланс run/grow/transform |

## Как выбирать

`team-strategy-doc` — самый полный документ, `team-vision` — одна его
секция, вынесенная отдельно, когда нужна только вдохновляющая часть без
полного диагноза. `investment-case` идёт после стратегии — сначала
решить, что делать (`team-strategy-doc`), потом просить под это
ресурсы (`investment-case`).

`org-design-principles` — не то же самое, что стратегические ставки:
принципы работают на каждое мелкое решение постоянно, ставки — на
несколько крупных решений раз в период. Плохой принцип не принуждает к
trade-off («будь user-centred» ничего не решает) — не принимать
формулировку без явной цены.

Для полного бизнес-канваса продукта (не функции внутри организации) —
см. `product-strategy` в соседнем блоке, другая задача и другой
масштаб.
