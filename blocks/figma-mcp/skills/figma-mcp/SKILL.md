# Подключение Figma

Своего MCP-сервера этот блок не заводит. Официальный плагин Figma уже несёт
и подключение, и рабочий набор скиллов — ставить его руками смысла нет
(`already-installed dependency`).

## Установка

```bash
claude plugin install figma@claude-plugins-official
```

Плагин ставит MCP-сервер (`https://mcp.figma.com/mcp`, OAuth без ключа —
`/mcp` → Authenticate → Allow Access) и скиллы `figma-use`,
`figma-create-new-file`, `figma-code-connect`, `figma-design-to-code`,
`figma-generate-design`, `figma-generate-diagram`, `figma-generate-library`,
`figma-implement-motion`, `figma-swiftui`, `figma-use-figjam`,
`figma-use-motion`, `figma-use-slides`.

Если плагин недоступен (нет доступа к официальному marketplace), вручную:

```bash
claude mcp add --transport http figma https://mcp.figma.com/mcp
```

Скиллы `figma-use`/`figma-generate-*` в этом случае не появятся — часть
блока `figma-canvas`, которая на них ссылается, работать не будет без них.

## Предупреждение про лимит вызовов

Figma ограничивает **удалённый** MCP-сервер по типу сиденья (seat) в
организации/файле, с которым работаешь, не по общей подписке:

- Starter / View / Collab-сиденье — **6 вызовов инструмента в месяц**.
- Dev / Full-сиденье — без лимита.

Тип сиденья смотреть в настройках конкретного файла/организации в Figma,
универсального способа проверить его отсюда нет. Некоторые скиллы из
`figma-canvas` (например `component-handoff`) тратят 20-35 вызовов за один
прогон — на Starter/View/Collab лимит выбьется за один запуск. Если агент
внезапно перестал видеть Figma-инструменты посреди работы, это первая
версия, которую стоит проверить.

## Базовые правила промпта

- Ссылку на фрейм или выделение в Figma передавай явно (`get_design_context`
  сам по себе работает с текущим выделением/переданной ссылкой, не с целым
  файлом).
- Структурируй сам Figma-файл под LLM: именованные слои, компоненты вместо
  детачнутых копий, переменные вместо захардкоженных значений — `figma-mcp`
  читает структуру файла, не только пиксели.
- Перед `use_figma` всегда сначала загружать сопутствующий скилл
  (`figma-use`, а для целых экранов/систем — `figma-generate-design` или
  `figma-generate-library`) — так требует сам официальный плагин, это не
  наша прихоть.

## Проверяемый результат (для /loop-build)

Готово — когда официальный MCP подключён и отвечает: список инструментов
содержит `figma-use`/`figma-generate-*`. Реальная проверка — вызов любого
figma-MCP инструмента без ошибки подключения, не suждение.

## Несколько задач сразу — не через этот блок

Сам блок — только подключение, задачи выполняют `figma-canvas` (тот же
файл, не параллелить — см. его карточку) или `figma-generate-*` (создание
нового файла — тут субагент на файл безопасен, разные файлы независимы).
