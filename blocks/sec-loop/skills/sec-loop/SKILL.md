# sec-loop

Автоматизирует стек `secure` тремя механизмами: гейт на выходе, цикл до нуля,
расписание. Проверяемый результат обязателен — иначе цикл не строится.

## 1. Stop-гейт (хук, уже активен блоком)

Хук `stop-gate.js` не даёт закончить сессию, если код менялся, а аудит не
прогнан. Напоминает один раз, дальше решение за тобой. Настройки не требует —
работает, пока блок включён.

## 2. Цикл аудит-фикс-тест до нуля

Крутит проход, пока критерий не выполнен. Критерий проверяемый:
**ноль CONFIRMED-находок И все sec-тесты зелёные**.

Один проход:
1. `/sec-audit` по изменённому (или по всему проекту).
2. Каждый CONFIRMED → `/sec-tests` (падающий тест) → фикс.
3. `/sec-attack` по localhost на пробитое — держит ли фикс.
4. Снова аудит. Ноль находок и зелёные тесты — стоп. Иначе новый проход.

Собирается через `/goal` и/или `/loop` (скилл `loop-build`). Условие остановки —
команда, а не ощущение: набор sec-тестов зелёный И в `docs/security/findings.json`
ноль записей с `verdict: CONFIRMED`. Оба факта проверяются командой, не глазами.

Модель, эффорт и количество под каждый шаг спрашиваются при запуске (правило). Перед началом работы покажи схему пользователю, чтобы убедиться, что ты будешь рабоать правильно.

Не строй цикл на непроверяемом условии («пока не станет безопасно»). Только на
команде с чётким выходом.

## 3. Расписание (cron)

Раз в неделю (или по договорённости) в фоне:
- деп-аудит: `npm audit` / `pip-audit` / аналог по стеку — новые уязвимости в
  зависимостях (пункт DE-1);
- проверка секретов в git-истории (SE-2);
- пакеты старше года (DE-1).

Ставится через скилл `schedule` (cloud-агент по cron). Отчёт — в `docs/security/` или куда скажешь. Находки на расписании не
чинятся молча: агент собирает список и ждёт разбора.

## Границы

- Цикл и расписание не удаляют и не переписывают файлы без подтверждения.
- Гейт только напоминает, не блокирует навсегда — обходится осознанно.
- Автофикс в цикле помечает изменения, прогоняет тесты после каждого (правило
  из AGENTS.md), откат при красных тестах.
