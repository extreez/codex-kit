# research-loop

Цикл поверх `research-deep`. Субагентов не заводит - управляет уже
существующими ролями блока (`research-investigator`, `research-critic`,
`research-patcher`), сам новых не создаёт.

## Условие остановки - файл, не ощущение

Состояние цикла - поле "Что будет считаться достаточным ответом" в
`docs/question.md`, не переписка и не память сессии. Поле пустое, `TODO` или
общая фраза без проверяемого критерия ("разобраться получше", "собрать
побольше источников") - цикл строить не из чего, тот же принцип, что в
`dev-loop` про `slices.json`. Сначала заполни его вместе с пользователем:
попроси сформулировать критерий так, чтобы его можно было сверить с текстом
отчёта - "закрыты аргументы за и против по каждому из трёх вариантов",
"названы риски по каждому пункту чек-листа X", а не общее ощущение полноты.

## Раунд

1. Есть `docs/research/notes/` не пустой (был хотя бы один раунд) - не
   начинай `research-deep` с нуля. Прочитай секцию "Что не покрыто" последнего
   `docs/research/report-*.md` и передай в `research-deep` как список
   конкретных подвопросов для нового прохода шагов 2-9 (декомпозиция и дальше),
   не весь пайплайн заново с шага 1.
2. Первый раунд или заметок нет - прогони `research-deep` целиком.
3. Модель и эффорт под роли внутри раунда - спроси перед запуском, правило
   то же, что в `research-deep` и во всех циклах codex-kit: не решать за
   владельца, предложить разумное.

## Проверка достаточности - отдельный шаг, не мнение research-deep о себе

`research-deep` заинтересован закрыть проход - как и любой субагент,
которого просят "готово или нет", он склонен решить, что готово. Та же
логика недоверия, что в `sec-audit`/`fact-check`: нужен отдельный шаг,
который не выполняет сам генератор отчёта.

После каждого раунда:

1. Прочитай секцию "Что не покрыто" из свежего отчёта.
2. Сверь её буквально с критерием из `docs/question.md` ("Что будет считаться
   достаточным ответом") - пункт за пунктом, не одним взглядом. Каждый пункт
   критерия либо закрыт текстом отчёта (сослаться, где), либо остаётся в
   "Что не покрыто".
3. Критерий выполнен целиком - цикл останавливается, отчёт остаётся как есть.
   Патчинг шёл по ходу раундов (patch-not-regenerate из `research-deep`), не
   одним махом в конце - переписывать отчёт на этом шаге не нужно.
4. Критерий не выполнен - новый раунд (шаг "Раунд" выше), целясь только в
   незакрытые пункты. Не начинай с декомпозиции всего вопроса заново, если
   часть подвопросов уже закрыта.

Не полагайся на фразу самого `research-deep` вида "исследование завершено" -
проверяй по тексту секции "Что не покрыто" и критерию из файла, а не по
итоговой реплике агента.

## Без присмотра - `/goal` поверх, условие читается из файла

Собери `/goal` по образцу `dev-loop`, условие - буквально из `docs/question.md`:

```
Условие: секция "Что не покрыто" в последнем docs/research/report-*.md
не содержит ни одного пункта из критерия "Что будет считаться достаточным
ответом" в docs/question.md - сверено построчно, не на ощущение. Каждый
раунд - новый проход research-deep по незакрытым пунктам, не с нуля. Стоп
после <N> раундов, N задать заранее (по умолчанию 3, если тема не дала
оценку сложнее).
Запусти: /goal <текст условия целиком>
```

Покажи оценку числа раундов и получи «да» от владельца, прежде чем набирать
`/goal` - блок не решает это за него.

## Границы

- Не удаляет и не переписывает `docs/research/notes/` и отчёты без
  подтверждения владельца.
- Не строит цикл на критерии, который нельзя сверить построчно с текстом
  отчёта ("пока не станет достаточно хорошо" - недостаточно, нужен список
  проверяемых пунктов).
- Не подменяет проверку достаточности мнением `research-deep` о собственной
  полноте.

## Соседи

Пайплайн одного раунда и субагенты - `research-deep`. Механизм самого цикла
(если нужен именно бесконтрольный прогон) - `loop-build`. Проверка цитат
внутри каждого раунда - `fact-check`, вызывается из `research-deep`, не
отсюда напрямую.
