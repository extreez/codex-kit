# Ревью риска перед стартом

2 техники из `pm-skills` (phuryn) для одной задачи — найти, что может
провалить план, пока есть время исправить. Разные методы, не
альтернативы: `pre-mortem` идёт от воображаемого провала назад к
причинам, `strategy-red-team` идёт от допущений плана вперёд к тестам.
Файлы в `templates/` дословно на английском, атрибуция в начале каждого.

## Какой метод когда

| Запрос пользователя | Файл | Метод |
|---|---|---|
| «проведи pre-mortem» | `templates/pre-mortem.md` | Представить провал через 14 дней → классифицировать риски (Tigers/реальные, Paper Tigers/раздутые, Elephants/невысказанные) → план действий для launch-blocking Tigers |
| «раскритикуй этот план» / «какие допущения провалят план» | `templates/strategy-red-team.md` | Вытащить несущие допущения плана → steelman → атака → ранжировать по (эффект × вероятность ошибки × дешевизна теста) → самый дешёвый тест на этой неделе |

## Как выбирать

`pre-mortem` лучше для готового плана перед запуском (продукт/фича с
датой релиза) — даёт action-план по срокам (launch-blocking / fast-
follow / track). `strategy-red-team` лучше для решения ещё в процессе
(стратегия, ставка, направление) — даёт не список рисков, а один
конкретный тест, который стоит прогнать на этой неделе.

Оба метода запрещают выдумывать слабость там, где план обоснован —
если допущение реально хорошо продумано, явно сказать это, не
генерировать риск ради количества.

Тот же приём Devil's Advocate (порог уступки по своему контраргументу)
уже используется в `research-deep`/`academic-review` — не тот же текст,
но сравнимая механика стресс-теста через самокритику.
