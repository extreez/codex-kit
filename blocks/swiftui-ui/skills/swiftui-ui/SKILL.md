# swiftui-ui

Ставится как есть, апстрим (`ameyalambat128/swiftui-skills`) не
копируется. Ситуативный блок, платформенный — не подключать в веб-проект.

**Важное отличие от остальных thin-wrapper блоков в каталоге:** источник
не статичный текст скилла, а извлечение реальной документации Apple прямо
из установленного на машине Xcode. Без Xcode установщик не сработает —
macOS-only ограничение, не опционально.

## Установка

```bash
curl -fsSL https://swiftui-skills.ameyalambat.com/install | bash
```

Альтернатива через общий установщик скиллов (тот же выбор runtime,
держать `Symlink (Recommended)`):

```bash
npx skills add ameyalambat128/swiftui-skills
```

## Почему не training data

Источник прямо формулирует причину существования: «SwiftUI is opinionated.
Most AI agents do not know those opinions... reduces hallucinated or
non-idiomatic SwiftUI». Извлекает внутреннюю документацию, которую Apple
поставляет внутри самого Xcode, а не пересказывает по памяти модели —
меньше устаревших/несуществующих API.

## Соседние блоки

`mobile-ui` — общие принципы мобильного UI без привязки к платформе,
использовать вместе, когда нужен и общий процесс дизайна, и нативный
Swift-код. `material3-ui` — тот же формат под Android/Jetpack Compose,
не пересекается (разные платформы, ставить один из двух по факту
проекта, не оба одновременно).

## Проверяемый результат (для /loop-build)

Реальная команда есть — Swift-код собирается: `xcodebuild build` или
`swift build` без ошибок. Соответствие HIG сверх компилируемости —
вердикт verifier-subagent, не команда (требует Xcode, macOS-only).

## Несколько экранов/View сразу — распараллелить

Разные SwiftUI View независимы по файлам — subagent на View, каждый
собирается и проверяется отдельно, коллизий по файлам нет.
