# geo-content

Контент для LLM читается иначе, чем для человека: модель вырезает
фрагмент из середины страницы и подаёт его как самостоятельный ответ —
если фрагмент без контекста не имеет смысла, его не процитируют.

## 15-пунктный чек-лист

| № | Пункт | Критерий закрытия |
|---|---|---|
| 1 | `llms.txt` в корне сайта | файл существует по адресу `/llms.txt`, формат см. `llms-txt` |
| 2 | `llms-full.txt` в корне сайта | существует полная версия для моделей, которые читают весь контент за раз, не только карту ссылок |
| 3 | H1 отражает основной интент страницы | H1 сформулирован так, чтобы совпадать с формулировкой вопроса, на который страница отвечает |
| 4 | H2-H3 по подинтентам | каждый подраздел закрывает один конкретный подвопрос темы, не произвольное деление текста |
| 5 | Атомизация абзацев | каждый абзац — самостоятельный ответ, ориентир 134-167 слов (см. обоснование диапазона в `geo-optimize/agents/citability-scorer.md` — тот же приём независимо найден в двух источниках) |
| 6 | Прямой ответ в первых 1-2 предложениях раздела | не «закапывать» вывод в конец абзаца — модель чаще берёт начало блока |
| 7 | Query Fan-Out — покрытие близких формулировок | страница отвечает не только на основной запрос, но и на его переформулировки/уточнения (синонимы, смежные вопросы «а что если», «чем отличается от») |
| 8 | Конкретные данные вместо общих утверждений | цифры, даты, названия вместо «значительно улучшает» |
| 9 | Мультимодальность — alt-тексты | описательные, не декоративные («диаграмма роста выручки с 2023 по 2026, рост втрое» вместо «картинка1») |
| 10 | Таблицы для сравнений/данных | там, где текст описывает сравнение нескольких вариантов — таблица, не абзац прозы (легче извлечь машиночитаемо) |
| 11 | Schema.org разметка | `Article`/`FAQPage`/`HowTo` на соответствующих типах страниц, валидна (см. `geo-optimize/agents/technical-schema-checker.md`) |
| 12 | `data-nosnippet` на уникальных данных, которые не должны утекать бесплатно | атрибут стоит на блоках с проприетарными цифрами/расчётами, если владелец хочет защитить их от бесплатного извлечения в AI-ответ без перехода на сайт |
| 13 | Автор и дата обновления видны | сигнал E-E-A-T, читается и человеком, и моделью как признак доверия |
| 14 | Внутренние ссылки на связанные ответы | страница ссылается на смежные подвопросы (Query Fan-Out превращается в сеть страниц, не только в один длинный текст) |
| 15 | Контент не противоречит другим страницам того же сайта | модель теряет доверие к источнику, если разные страницы дают разные ответы на один вопрос (сверить с `seo-content-maintenance`, cannibalized-диагноз — та же проблема с другой стороны) |

Готово — когда `grep` по сохранённому отчёту аудита показывает 0 строк
со статусом «не закрыто» (по образцу `checklist-design`, критерий
проверяем командой, не ощущением).

## Query Fan-Out — как применять на практике

Перед написанием/правкой раздела выпиши 3-5 переформулировок основного
вопроса раздела (синонимичные формулировки, уточняющие «почему»/«как»/
«чем отличается»). Если в тексте нет ответа хотя бы на 2 из них — раздел
неполный для GEO, даже если он полностью закрывает основной запрос:
LLM собирает ответ из фрагментов по смыслу запроса пользователя, который
редко совпадает дословно с заголовком статьи.

## Платформенная адаптация

Ключевая деталь методологии: домены, которые цитирует ChatGPT, Perplexity
и Google AI Overview, пересекаются между собой всего на ~11% (по данным
методологии, лежащей в основе `geo-optimize`). Одна и та же страница не
будет одинаково видна на всех платформах — не обещай универсальный
результат.

Что различается по платформам:
- **ChatGPT** (обучающая база + live-браузинг через `ChatGPT-User`/
  `OAI-SearchBot`) — ценит структурированность, прямые ответы, давность
  и стабильность источника.
- **Perplexity** — активно ходит по свежим страницам в момент запроса
  (`PerplexityBot`/`Perplexity-User`), сильнее реагирует на свежесть
  контента и явные цитаты/данные с указанием источника.
- **Google AI Overview** — использует существующий поисковый индекс,
  поэтому классический `seo-audit` (индексируемость, structured data)
  напрямую влияет на GEO-видимость здесь сильнее, чем на двух других
  площадках.

Если пользователь просит оптимизацию «под AI-поиск» без уточнения
платформы — уточни, есть ли приоритетная площадка (обычно видна из
аналитики рефералов, если она подключена), иначе работай по общему
15-пунктному чек-листу, который поднимает базовые сигналы сразу для всех
трёх, и явно скажи, что платформенной специфики без уточнения не будет.

## Отчёт

`docs/seo/geo-content-<дата>.md`: таблица чек-листа со статусами
(закрыт/не закрыто/не применимо) по каждой странице, список
Query Fan-Out переформулировок, которые не были покрыты, платформенные
рекомендации, если приоритетная площадка названа.

## Смежные блоки

`llms-txt` — сам формат файла из пункта 1-2 чек-листа. `geo-optimize` —
композитная оценка, куда попадают результаты этого чек-листа как часть
citability/E-E-A-T. `seo-content` — если запрос про позиции в органике,
не про AI-ответы, это другой блок с другой целью.

Контент публикуется через CMS со структурированными данными, не как
голый markdown - см. `library/seo-content-cms-tool/README.md` (Sanity
agent-toolkit).
