# seo-loop

Автоматизирует `seo-audit` двумя механизмами: гейт на выходе из сессии, цикл
до нуля. По образцу `sec-loop` из стека `secure`, адаптировано под SEO.

## 1. Stop-гейт (хук, уже активен блоком)

Хук `stop-gate.js` не даёт закончить сессию, если менялись страницы/шаблоны
(html/astro/vue/jsx/tsx/md/php, `sitemap.xml`, `robots.txt`), а `/seo-audit`
не прогнан. Напоминает один раз, дальше решение за тобой.

## 2. Цикл аудит-фикс-повторный обход до нуля

Крутит проход, пока критерий не выполнен. Критерий проверяемый: **ноль
находок severity blocker/high** в последнем отчёте `seo-audit`.

Один проход:
1. `/seo-audit` по изменённому (или по всему проекту).
2. Каждая находка blocker/high → фикс (техническая правка: robots/sitemap/
   canonical/meta/schema/alt — не переписывание контента без подтверждения).
3. Повторный обход изменённых страниц (перечитать после правки, пересобрать
   sitemap, если он менялся).
4. Снова `/seo-audit`. Ноль blocker/high — стоп. Иначе новый проход.

Собирается через `/goal` и/или `/loop` (скилл `loop-build`). Условие
остановки — команда, а не ощущение: перечитать свежий `docs/seo/audit-*.md`
и посчитать находки severity blocker/high, должно быть 0.

Модель, эффорт и количество субагентов под каждый шаг спрашиваются при
запуске (правило). Перед стартом покажи схему пользователю.

Medium/low находки цикл не гоняет до нуля — это не блокеры ранжирования,
решение по ним за пользователем отдельно (см. `seo-audit`, гейт 5-10
находок на проход — не всё сразу).

## 3. Контрольный прогон после нуля (drift-проверка)

Ноль blocker/high не значит «навсегда чисто» — canonical/robots/title
могут тихо измениться позже (правка шаблона, деплой, сторонний плагин).
Через N дней после закрытия цикла (по умолчанию 14, спроси пользователя,
если критично раньше/позже) прогони `/seo-audit` ещё раз и сравни свежий
`docs/seo/audit-*.md` с последним отчётом, закрывшим цикл:

- новые находки severity blocker/high, которых не было — открывают цикл
  заново с шага 1 (это регресс, не новая задача с нуля).
- вернулась находка, которая была закрыта фиксом — фикс не удержался
  (откатили правку, деплой перезаписал файл) — искать причину отката, не
  просто чинить повторно тем же способом.

Без SQLite/снапшотов — сравнение двух markdown-отчётов по находкам
достаточно для этой проверки, отдельное хранилище не нужно.

## Границы

- Цикл не переписывает контент без подтверждения — только техническую часть.
- Гейт только напоминает, не блокирует навсегда — обходится осознанно.
- Не путать с `geo-loop` (цикл для composite GEO-score, другая метрика и
  другая задача — цитируемость в LLM, не позиции в поиске).
