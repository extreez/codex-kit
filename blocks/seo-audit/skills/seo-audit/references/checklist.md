# Проверяемый чек-лист technical SEO

Пункт → что проверить → критерий закрытия. Каждый пункт — конкретное
действие, не общая формулировка. ID для ссылок из отчёта.

## Crawlability

| ID | Пункт | Критерий закрытия |
|---|---|---|
| CR-1 | `robots.txt` доступен и не блокирует нужные разделы | `curl /robots.txt` отдаёт 200, `Disallow` не закрывает страницы из sitemap |
| CR-2 | `robots.txt` не блокирует CSS/JS, нужные для рендера | нет `Disallow: /assets/` или аналога на файлы, влияющие на видимый контент |
| CR-3 | `sitemap.xml` существует и указан в `robots.txt` | строка `Sitemap:` есть, файл отдаёт 200 |
| CR-4 | `sitemap.xml` валиден | URL в нём отдают 200, не редиректят, не превышает 50k URL/50Мб на файл |
| CR-5 | Нет «сиротских» страниц | каждая страница из sitemap достижима по внутренней ссылке с другой проиндексированной страницы |
| CR-6 | Глубина клика с главной ≤3 для приоритетных страниц | обход внутренних ссылок от главной находит страницу за ≤3 перехода |
| CR-7 | Цепочки редиректов короче 3 прыжков, без циклов | `curl -IL` на ключевые URL показывает ≤2 промежуточных редиректа, конечный код 200 |

## Indexability

| ID | Пункт | Критерий закрытия |
|---|---|---|
| IX-1 | `noindex` стоит только там, где нужно | сверка списка `noindex`-страниц с намерением (служебные/дубли — да, целевые — нет) |
| IX-2 | `X-Robots-Tag` не противоречит meta robots | HTTP-заголовок и HTML-тег согласованы |
| IX-3 | Canonical указывает на предпочтительную версию | `<link rel="canonical">` без цепочек, совпадает с URL в sitemap |
| IX-4 | Параметризованные URL сведены к одному канониклу | `?utm_=`, `?sort=`, сессионные параметры не создают отдельно индексируемые копии |
| IX-5 | www/non-www, http/https сведены к одной версии | редирект 301 на канонический домен/протокол |
| IX-6 | hreflang взаимный (если мультиязычный сайт) | каждая языковая версия ссылается на все остальные и на себя (self-referencing) |

## Renderability

| ID | Пункт | Критерий закрытия |
|---|---|---|
| RN-1 | Критичный контент виден без выполнения JS ИЛИ рендерится предсказуемо | `curl` без JS отдаёт основной текст/заголовки, либо подтверждён SSR/SSG |
| RN-2 | Ключевые ссылки — настоящие `<a href>` | навигация и ссылки на товары/статьи не завязаны только на `onclick` |
| RN-3 | Render-blocking ресурсы не задерживают появление контента критично | синхронные скрипты в `<head>` не блокируют первую отрисовку контента на секунды |

## Signals

| ID | Пункт | Критерий закрытия |
|---|---|---|
| SG-1 | Title уникален и в пределах 50-60 символов | нет двух страниц с одинаковым title, длина в диапазоне |
| SG-2 | Meta description уникально, 140-160 символов | нет дублей, не keyword stuffing |
| SG-3 | Один H1 на страницу | ровно один `<h1>`, отражает тему страницы |
| SG-4 | Иерархия заголовков без пропуска уровней | H2 не идёт сразу после отсутствующего H1→H3 без H2 между |
| SG-5 | Structured data валиден и соответствует контенту | тестер разметки не выдаёт ошибок, тип схемы (Article/Product/FAQ/HowTo) соответствует видимому контенту |
| SG-6 | LCP-элемент определён и причина задержки названа | указан конкретный элемент и что его тормозит (сервер/ресурс/рендер) |
| SG-7 | CLS-источник определён | указан элемент, вызывающий сдвиг (реклама/шрифт/картинка без атрибутов размера) |
| SG-8 | INP-источник определён | указан обработчик/скрипт, блокирующий поток на долгих взаимодействиях |
| SG-9 | Alt-текст на контентных изображениях | декоративные — `alt=""` осознанно, контентные — описательный alt |
| SG-10 | Анкоры внутренних ссылок релевантны | не только «читать дальше»/«подробнее» на ссылках, ведущих на тематически разные страницы |

Найдено больше 5-10 нарушений за проход — см. правило гейта в `SKILL.md`
(шаг 7): в отчёт идут самые severity-критичные, остальное — списком «дальше
по списку» без раздувания отчёта.
