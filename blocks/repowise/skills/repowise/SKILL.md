# repowise

Ставится как есть — готовый CLI + MCP, не переписываем. Источник:
https://github.com/repowise-dev/repowise

## Шаг 0. Есть — используй, нет — поставь сам

Хук блока при старте сессии скажет, стоит ли `repowise` на машине. Не стоит —
поставь сам, не спрашивай пользователя читать документацию:

```bash
pip install repowise
repowise init --no-prose -y
```

`init` сам пишет `.mcp.json` в корне проекта и регистрирует repowise в
`~/.agents/settings.json` — руками ничего прописывать не нужно. На новой
машине с уже готовым проектом (`.mcp.json` уже есть, просто agent-профиль
не настроен):

```bash
repowise agents add --target=claude-code
```

Нужен Python (pip). Ставится один раз на машину, не на проект — повторный
`/kit add repowise` в другом проекте пропустит установку, `repowise --version`
уже отвечает.

## Что даёт агенту

MCP-инструменты вроде `get_overview`, `get_context`, `get_change_risk` —
агент запрашивает точечно, не читает файлы подряд. По источнику: -31.6%
токенов агента, 3.8 вместо 7.2 вызовов инструментов на задачу.

Работает локально, без вызовов LLM на сам граф — платный вызов модели нужен
только опционально, для написанной документации поверх графа.

## Конкуренты

`repowise` — рекомендованный выбор из группы «карта кода» (см.
`library/codebase-map/README.md`). Конкурирующие блоки той же задачи:
`socraticode`, `codegraph`, `graphify`, `understand-anything`. Держать
больше одного в проекте одновременно — смысла нет, все индексируют один и
тот же код. Группа зафиксирована в `CONFLICTS.md`.
