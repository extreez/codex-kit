# readme-badges

Ставится как есть — готовый CLI, детект стека и 100+ бейджей по провайдерам
уже написаны, переписывать своими силами не нужно (тот же принцип, что и с
`repowise`). Этот блок только объясняет, как звать инструмент, не заменяет
его.

Установка не нужна на каждый запуск:

```bash
npx shieldcn-cli
```

## Что умеет

**Генерация (по умолчанию)** — сканирует репозиторий (локально или по
GitHub-ссылке), сам определяет стек, выдаёт markdown с бейджами по
категориям — вставить прямо в README:

```bash
npx shieldcn-cli
npx shieldcn-cli https://github.com/<owner>/<repo>
```

Категории: GitHub (звёзды, лицензия, CI, контрибьюторы), Package (npm-версия,
скачивания, типы), Tooling (сборка, линтеры — по конфигам в репо), Stack
(зависимости → бренд-бейджи), Modern (ESM-only, monorepo, MCP-сервер),
Community (Discord, X, спонсоры).

**Migrate** — переносит уже стоящие бейджи shields.io на shieldcn:

```bash
npx shieldcn-cli migrate --dry   # сначала посмотреть, что изменится
npx shieldcn-cli migrate
```

**Init** — ставит маркеры в README, куда потом автообновлять бейджи без
ручной правки текста вокруг.

## Графики

Star-history, коммит-таймлайн, issue-трекинг, npm-скачивания — готовые SVG
без JS-зависимостей, через веб-редактор README Studio (shieldcn.dev) или
JSON-конфиг для CI-обновления.

## Когда бейджи не нужны

Приватный репозиторий без публичного npm/CI — часть категорий (Package,
Community) не даст данных, сканировать смысла нет. Для внутренних каталогов
(как сам `codex-kit`) — вручную статические бейджи по своим счётчикам
(`img.shields.io/badge/<label>-<value>-<color>`), не через shieldcn: тому
нечего сканировать без публичного стека.

## Соседи

Структура и порядок чтения README — `readme-polish`, этот блок только про
визуальные метки статуса внутри неё.
