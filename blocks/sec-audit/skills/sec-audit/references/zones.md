# Зоны аудита

Разбивка мастер-чеклиста (`sec-policy/references/checklist.md`) на зоны для
параллельных поисковиков. Одна зона = один субагент `sec-hunter`. Зоны не
пересекаются, чтобы находки не дублировались. Если несколько агентов на одну зону то нужен fork или worktree или branch, так, чтобы не пересикались.

Каждая зона: пункты чеклиста, что грепать (язык-агностик подсказки), где смотреть.

## Z1. Доступ и авторизация (AC-1..AC-4)
Грепать: обработчики маршрутов с `id`/`params`/`query`; вызовы БД по id;
проверки роли/прав; подключение Supabase/Firebase; наличие RLS-политик.
Смотреть: серверные роуты, middleware, миграции БД, правила BaaS.

## Z2. Аутентификация и сессии (AU-1..AU-4)
Грепать: форма входа, сравнение пароля, генерация/проверка токена, срок жизни
сессии, rate-limit на входе, сообщения об ошибке входа.
Смотреть: auth-модуль, middleware сессий, конфиг токенов.

## Z3. Секреты (SE-1..SE-3)
Грепать: присвоения ключей/токенов, импорт env, что уходит в бандл фронта,
`.gitignore`, история git.
Смотреть: фронт-код (что видно в браузере), конфиги, `.env*`.

## Z4. Ввод и вывод (IN-1..IN-5)
Грепать: SQL-строки со склейкой/интерполяцией, `innerHTML`,
`dangerouslySetInnerHTML`, вызовы шелла с вводом, работа с путями, `eval`,
`Function`, десериализация, запросы Mongo/Redis с объектом из ввода.
Смотреть: слой БД, рендер пользовательского текста, обработка файлов/команд.

## Z5. Загрузка файлов (UP-1)
Грепать: приём multipart/upload, проверка типа по имени, путь сохранения,
лимит размера.
Смотреть: обработчики загрузки, конфиг статики.

## Z6. Лимиты и деньги (RL-1..RL-3)
Грепать: rate-limit middleware, вызовы платных API, счётчики расхода на
пользователя, операции с балансом/промокодом/выводом, транзакции и блокировки.
Смотреть: эндпоинты платных операций, интеграции моделей/SMS.

## Z7. Внешние границы (EX-1..EX-5)
Грепать: обработчик вебхука, проверка подписи, конфиг CORS, redirect по URL из
запроса, серверные запросы по URL из ввода (SSRF: fetch/curl/загрузка по ссылке,
превью), CSRF-токен/SameSite на меняющих запросах.
Смотреть: вебхуки платёжек, CORS-конфиг, редиректы, серверные HTTP-клиенты, формы.

## Z8. Зависимости (DE-1..DE-3)
Грепать: манифест пакетов, lock-файл, даты обновления, чужие скиллы/плагины,
postinstall-скрипты, как ставит CI (из lock или нет).
Смотреть: package.json/requirements/go.mod/Gemfile, lock-файлы, CI-конфиг,
установленные скиллы. Прогнать аудитор пакетов (npm audit / pip-audit / аналог).

Не только уязвимость — тех-долг зависимостей тоже находка этой зоны, если
lock-файл отсутствует (сборка невоспроизводима) или пакет не обновлялся
дольше пары мажорных версий без причины. Severity ниже, чем у уязвимости,
но не молчать: раздел «Хардненинг» в отчёте, не «Подтверждённые».

## Z9. Эксплуатация (OP-1..OP-6)
Грепать: логирование критичных действий, `console.log`/отладка с данными,
разделение test/prod, конфиг бэкапов, флоу удаления аккаунта, выдача stack trace
в ответ.
Смотреть: логгер, конфиги окружений, релиз-скрипты, обработчик ошибок.

## Z10. Транспорт и заголовки (TR-1, HD-1, DP-1)
Грепать: конфиг HTTPS/TLS, HSTS, заголовки ответа (CSP, X-Frame-Options,
X-Content-Type-Options, Referrer-Policy), поля PII в ответах API, шифрование в
покое.
Смотреть: конфиг сервера/прокси, middleware заголовков, сериализаторы ответов.

## Z11. LLM / AI-фичи (AI-1..AI-4)
Только если проект ходит в модель. Грепать: куда идёт вывод модели (eval/SQL/
шелл/innerHTML/вызов инструмента), что кладётся в промпт (секреты, чужие данные),
права инструментов агента, изоляция векторного хранилища по тенантам.
Смотреть: слой вызова LLM, сборку промпта, определения инструментов, RAG-поиск.
Нет обращений к модели — зона не применима, отметь в отчёте.

## Детект стека (перед раздачей зон)

Определи, что искать конкретно, по маркерам:

| Маркер | Стек | Что добавить в фокус |
|---|---|---|
| `package.json`, `next.config` | Node/Next | бандл фронта, server actions, edge |
| `supabase`, `firebase` в зависимостях | BaaS | RLS/правила — зона Z1 критична |
| `requirements.txt`, `pyproject.toml` | Python | ORM, celery, шаблоны |
| `go.mod` | Go | database/sql, net/http |
| `Gemfile` | Ruby | ActiveRecord, ERB |
| `.sql`, `migrations/` | своя БД | параметризация, миграции |
| `Dockerfile`, `docker-compose` | контейнеры | секреты в образе, сеть |

Стека нет в таблице — работай по признакам угроз, они язык-агностик. При новом
стеке предложи создать проектный под-чеклист в `.agents/skills/sec-<стек>/`
(см. SKILL.md, шаг «самоадаптация»).
