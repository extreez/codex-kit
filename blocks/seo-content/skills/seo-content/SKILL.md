# seo-content

Четыре связанных этапа: от какие слова — к какие темы — к какой конкретный
текст — к массовой генерации, если модель контента это оправдывает.

## Этап 1. Keyword research — tiered + intent

Не один список ключей, а три яруса по объёму и конкурентности:

- **Head** — широкие, высокочастотные, высокая конкуренция («CRM»).
  Приоритет для бренда/пилларов, не для быстрой победы.
- **Body** — средний объём, средняя конкуренция («CRM для малого
  бизнеса»). Основной рабочий слой контент-плана.
- **Long-tail** — низкочастотные, конкретные, конвертят лучше
  («CRM для小 салона красоты бесплатно»). Быстрее ранжируются, вход для
  новых доменов.

На каждый ключ определи **intent** (что человек хочет получить):
- **Informational** — узнать («что такое CRM»).
- **Navigational** — найти конкретный сайт/бренд («Salesforce вход»).
- **Commercial investigation** — сравнить перед покупкой («лучшие CRM
  2026»).
- **Transactional** — купить/оформить («купить CRM подписку»).

Ключ без явного intent — не годится в бриф: контент не может решить, что
писать (обзорную статью или страницу с ценами), если непонятно, зачем
человек искал.

## Этап 2. Кластеризация — hub-and-spoke + gap-анализ

Группируй ключи в кластеры вокруг одной темы:

- **Hub** (пиллар) — одна широкая страница на весь кластер, покрывает
  тему целиком, линкует на все spoke-страницы.
- **Spoke** — узкие страницы под конкретные long-tail/body-ключи внутри
  темы, линкуют обратно на hub.
- Правило: один ключ — одна целевая страница. Два спока под один и тот
  же ключ — каннибализация, находка для `seo-content-maintenance`, не для
  нового плана.

**Gap-анализ**: сравни свои кластеры со страницами топ-конкурентов по тем
же ключам (можно опереться на `ux-research/competitor-profiling` — тот же
принцип URL-скрейпинга, специализированный под keyword/backlink gap).
Тема, которую конкуренты покрывают, а ты — нет, это приоритетный кандидат
в план.

## Этап 3. Content brief

На каждую целевую страницу — бриф, не голая тема:

- **Целевой ключ и intent** (из этапа 1).
- **SERP-анализ**: что уже ранжируется в топ-10 по этому ключу — формат
  (статья/список/инструмент/лендинг), примерный объём текста, какие
  подтемы освещают все топовые страницы (значит, ожидаются и у тебя).
- **Outline**: H2/H3-структура, отражающая подтемы из SERP-анализа плюс
  то, что конкуренты упустили (gap внутри страницы, не только между
  страницами).
- **Word count**: ориентир по медиане топ-10, не произвольное число —
  «пиши 2000 слов» без привязки к тому, что реально ранжируется, не бриф.
- **Внутренние ссылки**: на какой hub линковать, какие spoke-страницы
  ссылаться на эту.
- **Формат страницы соответствует intent**: informational-ключ - обзорная
  статья, не лендинг с ценами; transactional-ключ - страница с ценой и
  призывом к действию, не общая статья. Формат из SERP-анализа выше и
  intent из этапа 1 должны совпадать - если топ-10 по informational-ключу
  сплошь лендинги, это сигнал intent shift (см. `seo-content-maintenance`),
  бриф нужно пересобрать под новый формат, а не писать по старому шаблону.

## Этап 4. Гейт качества — E-E-A-T чек-лист

Перед публикацией сверь черновик с чек-листом (не бенчмарк конкретного
источника — собственный синтез на тему E-E-A-T: Experience, Expertise,
Authoritativeness, Trust):

| Признак | Проверка |
|---|---|
| Experience | Есть личный/практический опыт в тексте (не только пересказ чужих источников)? |
| Expertise | Автор/источник компетентен в теме — указан автор или экспертный источник? |
| Authoritativeness | Есть ссылки на первоисточники/данные, а не только мнение? |
| Trust | Дата публикации/обновления видна, факты проверяемы, нет вводящих в заблуждение заголовков? |
| Уникальность | Текст добавляет то, чего нет у топ-10 конкурентов (gap из этапа 2/3), не пересказ той же информации другими словами? |
| Полнота по outline | Все подтемы из брифа раскрыты, ни одна не превратилась в пустой абзац-заглушку? |
| Внутренние ссылки на месте | Hub↔spoke связи проставлены согласно кластеру? |

Не публикуй, пока хотя бы один пункт не «да» без явного обоснования, почему
это не применимо для конкретной страницы (например, product-страница без
даты обновления — нормально, справочная статья без даты — нет).

## Этап 5 (опционально). Programmatic SEO

Когда данных много, а страниц нужно много однотипных (город × услуга,
модель × характеристика) — генерируй по шаблону, а не пиши каждую руками.

1. Один валидированный шаблон страницы (структура из брифа выше, этап 3),
   не 50 экспериментальных вариантов.
2. Источник данных — таблица/API/CSV с уникальными значениями на каждую
   переменную (не дублирующиеся строки — иначе получится дублированный
   контент, находка `seo-audit`, слой Indexability).
3. Хотя бы один уникальный, не шаблонный блок на страницу (локальные
   данные, реальные цифры, а не только подстановка имени в общий текст) —
   иначе страницы схлопнутся в тонкий контент, который индексатор
   объединит или проигнорирует.
4. Прогони выборку сгенерированных страниц через гейт качества (этап 4)
   и через `seo-audit` (дубли, canonical) до массовой публикации всего
   набора.

## Смежные блоки

`seo-audit` — технический аудит уже существующих страниц (не создаёт
контент). `seo-content-maintenance` — цикл починки/обновления просевшего
контента (не новая стратегия). `geo-content` — адаптация контента под
цитируемость в AI-ответах, отдельная цель и отдельный чек-лист.
`ux-research/competitor-profiling` — общая механика конкурентного
URL-скрейпинга, здесь применяется под keyword/backlink gap.

Нужен реальный конвейер извлечения контента вместо ручного разбора
страницы - см. `library/seo-content-cms-tool/README.md` (Firecrawl).
