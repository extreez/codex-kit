# UX-исследователь и дизайнер

Генерация персон из данных исследования, карты пути, планирование
usability-тестов, синтез находок в рекомендации для дизайна.

## Триггерные фразы

- «создай персону пользователя»
- «сгенерируй персону из данных»
- «построй карту пути клиента»
- «отобрази путь пользователя»
- «спланируй usability-тест»
- «спроектируй исследование юзабилити»

## Воркфлоу 1: генерация персоны пользователя

**Ситуация:** есть данные о пользователях (аналитика, опросы, интервью),
нужна персона, обоснованная исследованием.

1. **Подготовить данные** в формате JSON:
   ```json
   [
     {
       "user_id": "user_1",
       "age": 32,
       "usage_frequency": "daily",
       "features_used": ["dashboard", "reports", "export"],
       "primary_device": "desktop",
       "usage_context": "work",
       "tech_proficiency": 7,
       "pain_points": ["slow loading", "confusing UI"]
     }
   ]
   ```

2. **Запустить генератор персон**:
   ```bash
   # Человекочитаемый вывод
   python scripts/persona_generator.py

   # JSON-вывод для интеграции
   python scripts/persona_generator.py json
   ```

3. **Проверить сгенерированные компоненты**:

   | Компонент | Что проверить |
   |---|---|
   | Архетип | Соответствует паттернам в данных? |
   | Демография | Выведена из реальных данных? |
   | Цели | Конкретные и применимые к делу? |
   | Фрустрации | Есть частотность? |
   | Выводы для дизайна | Дизайнер может по ним действовать? |

4. **Валидировать персону**: показать 3-5 реальным пользователям
   («это похоже на вас?»), сверить с тикетами поддержки, сверить с
   аналитикой.

5. **Справка:** `references/persona-methodology.md` — критерии валидности.

## Воркфлоу 2: карта пути пользователя

**Ситуация:** нужно визуализировать весь опыт пользователя ради
конкретной цели.

1. **Определить рамки**:

   | Элемент | Описание |
   |---|---|
   | Персона | Какой тип пользователя |
   | Цель | Чего он добивается |
   | Старт | Триггер, запускающий путь |
   | Финиш | Критерий успеха |
   | Временной охват | Часы/дни/недели |

2. **Собрать данные о пути**: интервью («проведите меня через…»),
   записи сессий, аналитика (воронка, отвалы), тикеты поддержки.

3. **Разметить стадии** — типичный B2B SaaS: Awareness → Evaluation →
   Onboarding → Adoption → Advocacy.

4. **Заполнить слои для каждой стадии**:
   ```
   Стадия: [Название]
   ├── Действия: что делает пользователь?
   ├── Точки контакта: где происходит взаимодействие?
   ├── Эмоции: как он себя чувствует? (1-5)
   ├── Болевые точки: что фрустрирует?
   └── Возможности: где можно улучшить?
   ```

5. **Найти возможности**: приоритет = частота × тяжесть × решаемость.

6. **Справка:** `references/journey-mapping-guide.md` — шаблоны.

## Воркфлоу 3: планирование usability-теста

**Ситуация:** нужно провалидировать дизайн на реальных пользователях.

1. **Сформулировать вопросы исследования** — превратить размытую цель в
   проверяемый вопрос:

   | Размыто | Проверяемо |
   |---|---|
   | «Легко ли этим пользоваться?» | «Может ли пользователь пройти checkout за <3 мин?» |
   | «Нравится ли пользователям?» | «Выберут ли пользователи дизайн A или B?» |
   | «Это понятно?» | «Найдёт ли пользователь настройки без подсказок?» |

2. **Выбрать метод**:

   | Метод | Участники | Длительность | Для чего |
   |---|---|---|---|
   | Модерируемый удалённый | 5-8 | 45-60 мин | Глубокие инсайты |
   | Немодерируемый удалённый | 10-20 | 15-20 мин | Быстрая валидация |
   | Партизанский | 3-5 | 5-10 мин | Быстрый фидбек |

3. **Спроектировать задания** в формате сценария:
   ```
   СЦЕНАРИЙ: «Представьте, что вы планируете поездку в Париж…»
   ЦЕЛЬ: «Забронируйте отель на 3 ночи в своём бюджете.»
   УСПЕХ: «Вы видите страницу подтверждения.»
   ```
   Прогрессия заданий: разминка → основное → второстепенное → крайний
   случай → свободное исследование.

4. **Определить метрики успеха**:

   | Метрика | Целевое значение |
   |---|---|
   | Доля завершивших | >80% |
   | Время на задачу | <2× ожидаемого |
   | Доля ошибок | <15% |
   | Удовлетворённость | >4/5 |

5. **Подготовить гид модератора**: инструкции think-aloud, неведущие
   подсказки, вопросы после задачи.

6. **Справка:** `references/usability-testing-frameworks.md` — полный
   гид.

## Воркфлоу 4: синтез исследования

**Ситуация:** есть сырые данные (интервью, опросы, наблюдения), нужны
применимые выводы.

1. **Закодировать данные**, тегируя каждый пункт: `[ЦЕЛЬ]`,
   `[БОЛЬ]`, `[ПОВЕДЕНИЕ]`, `[КОНТЕКСТ]`, `[ЦИТАТА]` (дословные слова
   пользователя).

2. **Сгруппировать похожие паттерны** в кластеры (например, Power Users
   vs Casual User).

3. **Посчитать размер сегментов**:

   | Кластер | Пользователей | % | Жизнеспособность |
   |---|---|---|---|
   | Power Users | 18 | 36% | Основная персона |
   | Бизнес-пользователи | 15 | 30% | Основная персона |
   | Casual Users | 12 | 24% | Вторичная персона |

4. **Выделить ключевые находки** по каждой теме: формулировка,
   подтверждающие данные (цитаты), частотность (X/Y участников),
   влияние на бизнес, рекомендация.

5. **Приоритизировать возможности** по шкале 1-5: частота, тяжесть,
   охват, решаемость.

6. **Справка:** `references/persona-methodology.md` — фреймворк
   анализа.

## Справка по инструменту: persona_generator.py

Генерирует персоны, обоснованные данными исследования.

| Аргумент | Значения | По умолчанию | Описание |
|---|---|---|---|
| format | (нет), json | (нет) | Формат вывода |

Генерируемые архетипы:

| Архетип | Сигналы | Фокус дизайна |
|---|---|---|
| power_user | Ежедневное использование, 10+ фич | Эффективность, кастомизация |
| casual_user | Еженедельное использование, 3-5 фич | Простота, подсказки |
| business_user | Рабочий контекст, командное использование | Коллаборация, отчётность |
| mobile_first | Основное устройство — мобильное | Тач, офлайн, скорость |

Компоненты вывода: demographics, psychographics, behaviors,
needs_and_goals, frustrations, scenarios, design_implications,
data_points (объём выборки и уровень уверенности).

## Быстрые справочные таблицы

**Выбор метода исследования**

| Тип вопроса | Лучший метод | Размер выборки |
|---|---|---|
| «Что делают пользователи?» | Аналитика, наблюдение | 100+ событий |
| «Почему они это делают?» | Интервью | 8-15 пользователей |
| «Насколько хорошо они справляются?» | Usability-тест | 5-8 пользователей |
| «Что они предпочитают?» | Опрос, A/B-тест | 50+ пользователей |
| «Что они чувствуют?» | Дневниковое исследование, интервью | 10-15 пользователей |

**Уровни уверенности в персоне**

| Размер выборки | Уверенность | Применение |
|---|---|---|
| 5-10 пользователей | Низкая | Разведочное |
| 11-30 пользователей | Средняя | Направляющее |
| 31+ пользователей | Высокая | Продуктивное |

**Тяжесть usability-проблемы**

| Тяжесть | Определение | Действие |
|---|---|---|
| 4 — критическая | Мешает завершить задачу | Чинить немедленно |
| 3 — значительная | Существенная сложность | Чинить до релиза |
| 2 — незначительная | Вызывает заминку | Чинить по возможности |
| 1 — косметическая | Заметна, но не мешает | Низкий приоритет |

**Типы вопросов интервью**

| Тип | Пример | Для чего |
|---|---|---|
| Контекст | «Проведите меня через типичный день» | Понять среду |
| Поведение | «Покажите, как вы делаете X» | Наблюдать реальные действия |
| Цели | «Чего вы пытаетесь достичь?» | Вскрыть мотивацию |
| Боль | «Что самое сложное?» | Найти фрустрации |
| Рефлексия | «Что бы вы изменили?» | Генерировать идеи |

## Чек-лист качества

**Персона:** основана на 20+ пользователях (минимум), минимум 2
источника данных (количественный + качественный), конкретные и
применимые цели, у фрустраций есть частотность, выводы для дизайна
конкретны, указан уровень уверенности.

**Карта пути:** рамки чётко определены (персона, цель, временной
охват), основана на реальных данных, а не допущениях, заполнены все
слои (действия, точки контакта, эмоции), болевые точки найдены на
каждой стадии, возможности приоритизированы.

**Usability-тест:** вопросы исследования проверяемы, задания —
реалистичные сценарии, а не инструкции, 5+ участников на дизайн,
метрики успеха определены, находки включают оценку тяжести.

**Синтез исследования:** данные закодированы последовательно, паттерны
опираются на 3+ точки данных, у находок есть подтверждение,
рекомендации применимы, приоритеты обоснованы.
