# Перенос и пунктуация

Где начинаются строки, где кончаются, где переносятся и какие символы
используют.

## Measure (длина строки)

Длинные строки затрудняют взгляду поиск начала следующей. Для
длинноформатного текста цель — 60-75 символов в строке.

Подойдёт любая единица. `65ch` измеряет символы напрямую — один `ch` это
ширина `0` в текущем шрифте, а предел в пикселях или rem не хуже. При
размере тела `16px` диапазон 60-75 символов ложится примерно между `560px`
и `680px` в зависимости от шрифта, так что у Tailwind подходят и
`max-w-xl` (`576px`), и `max-w-2xl` (`672px`). Важно, что предел
существует и длина строки попадает в диапазон. Перепроверять при смене
размера шрифта тела.

## Выравнивание

`text-align` управляет тем, где начинается и кончается каждая строка.
`justify` растягивает пробелы, пока оба края не выровняются — работает в
конкретных editorial-layout и больше нигде в интерфейсе.

## Перенос

| Свойство | Использование |
| --- | --- |
| `text-wrap: balance` | Распределяет текст ровно по нескольким строкам |
| `text-wrap: pretty` | Не даёт одинокому короткому слову остаться на последней строке |
| `overflow-wrap: break-word` | Даёт длинным словам, ссылкам и ID переноситься, не вылезая за контейнер |
| `white-space: nowrap` | Держит лейблы и бейджи в одну строку там, где перенос выглядит поломкой |

Использовать `balance` на заголовках и `pretty` на описаниях. Пропускать
оба в длинноформатном тексте — браузеры всё равно игнорируют `balance`
дальше нескольких строк, а выравнивание целого абзаца тратит пространство
и усложняет чтение.

## Усечение

- Одна строка: `text-overflow: ellipsis`, требует `overflow: hidden` и
  `white-space: nowrap`.
- Несколько строк: `line-clamp` допускает любое число строк до
  многоточия.

Усечение прячет контент. Где пропущенное значение важно — делать полное
значение доступным в тултипе или развёрнутом виде.

## Регистр

`text-transform` меняет отображаемый регистр, не меняя сам текст. Писать
копию естественно и управлять представлением через CSS, чтобы редизайн
никогда не означал переписывание текста.

## Умная пунктуация

Клавиатурные символы — не всегда лучшие символы:

| Вместо | Использовать |
| --- | --- |
| Прямые кавычки `"..."` | Изогнутые кавычки, огибающие текст (прямые оставить в коде) |
| Дефис в диапазонах | En dash: `2010–2020` |
| Два дефиса для вставки | Символ em dash |
| Три точки `...` | Одиночный символ многоточия `…` |
| Обычный пробел в `16 px` | `&nbsp;`, чтобы значение никогда не разрывалось |
| Неконтролируемые переносы слов | `&shy;`, чтобы отметить, где слово может разбиться |

## Интернационализация

Два уточнения для текста смешанного направления:

- **Длинные абзацы выравниваются по собственному языку.** Фрагмент в одну-
  две строки следует направлению окружающего UI. Абзац из трёх и более
  строк выравнивается по своему собственному письму — английский абзац
  остаётся start-aligned LTR даже внутри RTL-интерфейса. `text-align: start`
  с верными `lang`/`dir` на элементе абзаца решает это.
- **Никогда не переворачивай цифры.** Числа сохраняют порядок в любом
  направлении, так что номер телефона или «541» читается одинаково в RTL.
  Браузеры обрабатывают это через алгоритм bidi Unicode. Никогда не
  бороться с ним ручной перестановкой, оборачивать смешанные
  числа-и-текст значения в `<bdi>` там, где соседний RTL-текст их
  искажает.
