# Отступы и адаптивность

Пространство между контролами, margins против viewport, намёки на
закадровый контент и layout, переживающий ресайз и перевод.

## Пространство для дыхания между таргетами

Слишком тесно расставленные контролы промахиваются при тапе и читаются как
единое целое. Где у проекта нет density-шкалы, начни отсюда:

| Между чем | Отправная точка |
| --- | --- |
| Соседние контролы с рамкой/заливкой (кнопки, инпуты) | `12px` |
| Вокруг безрамочных контролов (текстовые кнопки, иконки) | `24px` |
| Несвязанные группы контролов | `24px`+ (2× внутригруппового отступа) |

Безрамочным контролам нужно больше зазора, потому что ничто не отмечает,
где кончается один таргет и начинается следующий — пространство и есть
граница. Компактные профессиональные инструменты могут использовать
меньше, пока hit-area остаются отличимыми и никогда не перекрываются.
Сохраняй сложившуюся, пригодную density, а не растягивай контролы под эти
значения.

```html
<!-- Хорошо: кнопки с рамкой на 12px, иконочным кнопкам дан простор -->
<div class="flex gap-3">
  <button class="rounded-lg border px-4 py-2">Отмена</button>
  <button class="rounded-lg bg-blue-600 px-4 py-2 text-white">Сохранить</button>
</div>

<!-- Плохо: три безрамочные иконочные кнопки сжаты на 4px -->
<div class="flex gap-1">
  <button><TrashIcon /></button>
  <button><ArchiveIcon /></button>
  <button><ShareIcon /></button>
</div>
```

Требования WCAG к размеру таргета, увеличенные usability-таргеты и
расширение псевдоэлементом — забота `web-a11y-code`; эти зазоры —
дополнение к ним, так что расширенные hit-area никогда не перекрываются.

## Отступай кнопки от краёв

В content-layout кнопки, прижатые к viewport, выглядят как системный
chrome и обрезаются на скруглённых углах или в зонах жестов. Держи их
внутри layout margins. Edge-to-edge действия остаются валидными там, где
это намеренно платформенный chrome с учётом safe area:

```css
/* Хорошо: отступлённая панель действий */
.action-bar {
  padding-inline: 16px;
  padding-bottom: calc(16px + env(safe-area-inset-bottom));
}
.action-bar button { width: 100%; border-radius: 12px; }

/* Плохо: кнопка приклеена ко всем трём краям */
.action-bar button {
  width: 100vw;
  border-radius: 0;
  position: fixed;
  bottom: 0;
}
```

Начинай с `16px` inline margin на мобильном, если у проекта нет своего
layout-токена. Кнопка всё равно может занимать всю ширину контента внутри
этих margins.

## Progressive disclosure нуждается в аффордансе

Прятать сложность — хорошо; прятать без сигнала — ловушка. Каждый кусок
закадрового или свёрнутого контента нуждается в видимом намёке на своё
существование. Держи сложившийся в продукте индикатор скролла или паттерн
disclosure, рецепты ниже — только когда сигнала нет вообще:

- **Выглядывающие элементы.** В горизонтальном скроллере или карусели
  размести элементы так, чтобы следующий «выглядывал» на `16-32px` за край
  контейнера. Ряд карточек, кончающийся ровно у края, выглядит завершённым
  — его никто не скроллит.
- **Disclosure-контролы.** Свёрнутые секции получают шеврон или «Показать
  ещё», с указанием, что скрыто: «Показать ещё 12 результатов», не
  «Ещё».
- **Сигналы усечения.** Обрезанный текст показывает многоточие и способ
  развернуть. Механика усечения — забота `typography`.

В рецепте выглядывающего скроллера padding контейнера создаёт выглядывание,
snap-точки остаются на краю контента.

```css
.scroller {
  display: flex;
  gap: 12px;
  overflow-x: auto;
  padding-inline: 24px;
  scroll-padding-inline: 24px;
  scroll-snap-type: x mandatory;
}
.scroller > * {
  flex: 0 0 calc(100% - 48px - 24px); /* контейнер минус margins минус выглядывание */
  scroll-snap-align: start;
}
```

```html
<!-- Tailwind: ширина 80% держит выглядывание следующей карточки на 16-32px -->
<div class="flex gap-3 overflow-x-auto px-6 [scroll-padding-inline:1.5rem] snap-x snap-mandatory">
  <div class="w-[80%] shrink-0 snap-start">…</div>
  <div class="w-[80%] shrink-0 snap-start">…</div>
</div>
```

## Контент течёт до края, контролы плавают

Два слоя ведут себя по-разному у краёв:

- **Слой контента**: фоны, hero-медиа и скроллируемые списки простираются
  до краёв viewport.
- **Слой контролов**: текст и контролы остаются внутри layout margins и
  safe area, плавая поверх.

```css
/* Хорошо: full-bleed медиа внутри ограниченной статьи */
.article {
  display: grid;
  grid-template-columns: 1fr min(65ch, calc(100% - 48px)) 1fr;
}
.article > * { grid-column: 2; }
.article > .full-bleed { grid-column: 1 / -1; }
```

Sticky-заголовки и floating action buttons учитывают safe area:

```css
.fab {
  position: fixed;
  inset-inline-end: calc(16px + env(safe-area-inset-right));
  bottom: calc(16px + env(safe-area-inset-bottom));
}
```

## Держи структуру, пока не сломается

Breakpoints принадлежат контенту, не каталогу устройств:

- Ломай там, где layout реально перестаёт помещаться, не на `768px`,
  потому что так говорит пресет. Это там, где сайдбар сжимает контент ниже
  минимальной меры, или где card-grid падает ниже пригодной ширины колонки.
- Схлопывай поздно. Layout, держащий развёрнутую структуру, пока она
  реально помещается, остаётся стабильным и знакомым. Преждевременное
  схлопывание выбрасывает пространство, за которое заплатил пользователь.
- Предпочитай **container queries** для компонентов. Карточка адаптируется
  к колонке, в которой находится, не к viewport.

```css
/* Хорошо: компонент адаптируется к своему контейнеру */
.card-list { container-type: inline-size; }
@container (max-width: 400px) {
  .card { grid-template-columns: 1fr; }
}

/* Плохо: media query по viewport ломает карточку внутри узкого сайдбара */
@media (max-width: 768px) {
  .card { grid-template-columns: 1fr; }
}
```

Тестируй сначала самый маленький и самый большой поддерживаемый размер —
они ломаются первыми, затем размеры между ними.

## Планируй рост и обрезание

Layout проваливается в двух направлениях. Контент растёт, viewport
сжимается.

**Рост строки зависит от языка и от длины исходной строки.** Никогда не
полагайся на один универсальный процент.

- Никаких фиксированных ширин, подогнанных под английские лейблы.
  `max-width` плюс перенос.
- Никаких фиксированных высот у текстовых контейнеров. `min-height`, где
  нужен пол.
- Кнопки определяют свой размер из лейбла (`padding-inline`), никогда
  захардкоженная ширина.
- Тестируй с псевдо-локализацией или локалью с длинными строками перед
  сдачей.

```css
/* Хорошо: лейбл определяет размер */
.button { padding-inline: 16px; white-space: nowrap; }

/* Плохо: немецкий переполнится или обрежется */
.button { width: 96px; overflow: hidden; }
```

**Обрезание.** Никогда не помещай критичное действие туда, где его можно
обрезать: нижний край изменяемой панели, ниже сгиба модалки фиксированной
высоты, за раскрывающейся клавиатурой. Держи основные действия в
стабильном chrome, sticky-футере с safe-area padding или в верху экрана.
Там, где контент модалки скроллится, её строка действий — нет.
