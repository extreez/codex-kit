# tgrep

Ставится как есть, готовый CLI на Rust, не переписываем. Источник:
https://github.com/microsoft/tgrep

Заменяет не карту кода, а встроенный Grep. Триграммный индекс отбирает файлы,
которые могут содержать совпадение, и regex гоняется только по ним.

## Шаг 0. Порог. Ниже него блок не нужен

Индекс окупается на крупных репозиториях. Замеры автора (BENCHMARKS.md,
24 августа 2026, GitHub-раннеры, ускорение против ripgrep):

| Репозиторий | Файлов | Windows | macOS | Linux |
|---|---:|---:|---:|---:|
| chromium | 504 351 | 17.6x | 15.8x | 3.81x |
| gecko-dev | 387 841 | 38.6x | 51.9x | 7.36x |
| linux | 95 831 | 34.8x | 21.0x | 9.38x |
| rust | 62 326 | 7.69x | 2.69x | 1.61x |
| kubernetes | 31 300 | 7.08x | 2.81x | 0.93x |
| go | 15 833 | 7.53x | 3.12x | 1.29x |

Читать так: на Windows выигрыш есть уже на 16 000 файлов, на Linux он
появляется ближе к 100 000. Kubernetes на Linux единственная клетка, где
ripgrep выигрывает (0.93x).

Правило: **считай файлы до того, как строить индекс.**

```bash
git ls-files | wc -l          # в git-репозитории
```

Меньше 15 000 файлов, значит индекс не строить и блок не трогать. Встроенный
Grep справится, а постройка индекса и фоновый сервер съедят выигрыш. Не
уговаривай пользователя ставить tgrep на мелкий проект.

## Шаг 1. Установка

Хук блока при старте сессии скажет, стоит ли `tgrep` на машине и есть ли
индекс. Не стоит, поставь сам, не отправляй пользователя читать документацию.

```powershell
# Windows
gh release download --repo microsoft/tgrep -p '*windows*' -D $env:TEMP\tgrep-dl
Expand-Archive $env:TEMP\tgrep-dl\tgrep-*-windows*.zip -DestinationPath $HOME\.cargo\bin -Force
```

```bash
# macOS
brew install tgrep
```

```bash
# любая платформа, если есть Rust
cargo install --path tgrep-cli --locked   # из клона репозитория
```

Linux и Intel/ARM-сборки лежат в GitHub Releases того же репозитория.
Ставится один раз на машину, не на проект.

## Шаг 2. Индекс и сервер

```bash
tgrep index .        # построить индекс, кладётся в <корень>/.tgrep
tgrep serve . &      # держит индекс горячим, следит за файлами
tgrep status .       # PID, порт, число файлов, состояние вотчера
```

Сервер поднимается один раз за сессию. Не можешь держать фоновый процесс,
обходись `tgrep index .` и перестраивай после крупных правок.

Добавь `.tgrep/` в `.gitignore` проекта, индекс в репозиторий не едет.

## Шаг 3. Поиск

Порядок аргументов из `AGENTS.md` источника: **флаги, потом `--`, потом
паттерн, потом путь.** `--` обязателен, иначе паттерн вида `-foo` уедет в
разбор флагов.

```bash
tgrep -l -- 'handlePayment' .              # только имена файлов
tgrep --vimgrep -- 'fn \w+_handler' src    # file:line:col:text
tgrep -F -- 'user.id' .                    # литерал, без regex
tgrep -l -i -g '*.ts' -- 'usequery' .      # регистр не важен, только .ts
tgrep --json -- 'TODO' .                   # построчный JSON как у ripgrep
```

Флаги совпадают с ripgrep: `-i` регистр, `-F` литерал, `-w` целое слово,
`-v` инверсия, `-m N` предел совпадений, `-c` счёт, `-o` только совпадение,
`-A/-B/-C` контекст, `-t` тип файла, `-g` глоб, `-U` многострочный,
`-P` движок PCRE2, `--stats` план запроса, `--no-index` в обход индекса.

Порядок работы на сложном запросе: сначала `-l`, посмотреть список файлов,
потом точечный поиск внутри них. Символ или строку от пользователя искать с
`-F`, иначе спецсимволы разъедутся в regex.

**Коды выхода: 0 нашлось, 1 не нашлось, 2 ошибка.** Единица это не сбой,
а пустой результат. Читай и stdout, и stderr: предупреждение о протухшем
индексе приходит рядом с результатами.

## Хук блока

`suggest-tgrep.js` висит на `PreToolUse` с matcher `Grep`. Если в корне
проекта есть `.tgrep`, хук отдаёт готовую команду `tgrep` с уже
переведёнными флагами вызванного Grep. Не блокирует, подсказывает.

Индекса нет, значит хук молчит целиком, оверхед нулевой. Подсказка
приходит первые три раза за сессию, дальше не шумит.

Хук существует потому, что одного правила в этом файле мало: встроенный
Grep дешевле по вызову, и без напоминания в момент поиска он выигрывает
привычкой.

## Границы

Не входит в группу `codebase-map` (`repowise`, `socraticode`, `codegraph`,
`graphify`, `understand-anything`). Те строят структуру и связи, tgrep
ускоряет точное совпадение строк. Задачи разные, вместе не спорят, держать
одновременно можно. Зафиксировано в `CONFLICTS.md`.

Нужен поиск по смыслу («где обрабатывается оплата»), это `socraticode`.
Нужна структура и риск изменения, это `repowise`.
