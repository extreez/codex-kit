# Приёмочный прогон

Один конкретный ролик, который проходит конвейер целиком. Собрался значит
система работает. Сломался значит видно, на каком шаге.

Три применения: критерий готовности, регрессия после обновления чужих
инструментов, первая проверка после установки.

## Задание

| Параметр | Значение |
|---|---|
| Бриф | «пятнадцать секунд про то, как ставится ffmpeg на Windows» |
| Формат | 1080x1920, 30 fps |
| Длительность | 15 секунд ровно |
| Планов | 4 |
| Голос | русский, закадровый |
| Звук | 2 эффекта из библиотеки |
| Титры | заголовок и подпись |
| Выход | `out/final.mp4` и `out/final.xml` |

Ручных действий ровно четыре: подтверждение сценария, раскадровки,
черновика, финала. Плюс подтверждение сметы перед генерацией.

## Шаги и что проверяется на каждом

| Шаг | Проверка | Провал выглядит так |
|---|---|---|
| `route` | список шагов показан, пропущенные названы с причиной | шаг молча пропал или крутится без входа |
| `script` | сумма длительностей битов равна 15.0 | сумма 14.3 или 16.8 |
| `storyboard` | 4 артборда на холсте, сумма планов равна 15.0 | планов 3 или сумма не сходится |
| смета | цена показана до списания | генерация ушла без подтверждения |
| генерация | 4 шота в `shots/` | файлов меньше четырёх |
| `sound` | голос длиннее нуля, 2 эффекта на месте | тишина или эффекты не нашлись |
| сборка | композиция HyperFrames открывается в `preview` | ошибка разметки |
| `render` | `out/final.mp4` длится 15.0 плюс-минус 0.1 | длительность уехала |
| `export_fcp7.py` | `out/final.xml` открывается в DaVinci | XML не парсится или дорожки пустые |

## Проверка результата командой

Длительность и разрешение:

```bash
ffprobe -v error -show_entries format=duration -show_entries stream=width,height -of default=noprint_wrappers=1 out/final.mp4
```

Ждём `width=1080`, `height=1920`, `duration` около 15.

XML разбирается стандартной библиотекой, без сторонних пакетов:

```bash
python -c "import xml.etree.ElementTree as E; r=E.parse('out/final.xml').getroot(); print(r.tag, len(r.findall('.//clipitem')), 'клипов')"
```

Ждём `xmeml` и не ноль клипов.

Самопроверка трёх скриптов блока:

```bash
python scripts/loop_check.py --demo && python scripts/transcribe_local.py --demo && python scripts/export_fcp7.py --demo
```

Все три печатают «самопроверка пройдена».

Внешний стек:

```bash
bash ../../apps/video-stack/check.sh
```

Код выхода 0 или 2. Код 1 значит конвейер не поедет.

## Отдельно: прогон лупа

Приёмочный ролик луп не проверяет, там прямая склейка. Луп гоняется своим
заданием: 4 секунды, бесшовный, генерация с совпадающими первым и
последним кадром.

```bash
python scripts/loop_check.py out/loop.mp4
```

Код выхода 0 значит шва нет. Код 1 значит луп не принят.

## Когда прогон обязателен

- После установки стека, до первого настоящего проекта.
- После обновления HyperFrames или video-use.
- После правки любого из трёх скриптов блока.
- Перед тем как объявить конвейер рабочим кому-то ещё.

## Грабли, найденные первым прогоном

Все четыре пункта прошли `hyperframes check` не с первого раза. Проверяй
их до рендера, а не после.

| Симптом | Код линтера | Причина и что делать |
|---|---|---|
| Рендер вышел немым | `media_missing_id` | у `<audio>` нет `id`. Микшер выбирает `audio[id][src]`, элемент без id не попадает в звук вообще |
| План чернеет в середине своего окна | нет, линтер молчит | на самом таймлайн-медиа тянули размер. Анимировать размеры `<video class="clip">` нельзя, подстановка кадров ломается. Наезд вешать на нетаймлайновую обёртку |
| План показывает не те кадры и пропадает | `video_nested_in_timed_element` | `<video data-start>` внутри обёртки, у которой тоже есть `data-start`. Тайминг ставится либо на обёртку, либо на видео |
| Шрифт подменился | `font_family_without_font_face` | шрифта нет в автоподставляемом списке. Рендер молча возьмёт запасной и типографика уедет |

Ещё два, которые линтер не ловит по определению.

**Закадровый текст меряется в секундах, а не в знаках.** Первый вариант
сценария на четыре бита дал 24.1 секунды речи при бюджете 15. Порядок
работы такой: синтезировать голос, измерить `ffprobe`, потом ставить
тайминги планов по факту. Не наоборот.

**Ошибка линтера гасит остальные проверки.** При ненулевом числе ошибок
`check` пишет `0 sample(s)` и `0/0 text checks`. Это выглядит как чистый
файл, но значит, что аудит раскладки и контраста просто не запускался.
Верить этим числам можно только после нуля ошибок.

## Чего прогон не проверяет

Качество ролика. Он проверяет, что конвейер доводит задание до файла, а не
что получилось красиво. Красоту решает человек на четырёх стопах.
