# dev-loop

Автоматизирует стек `dev` двумя механизмами: гейт на выходе, цикл по срезам.
Проверяемый результат обязателен — иначе цикл не строится, тот же принцип,
что в `loop-build`.

## 1. Stop-гейт (хук, уже активен блоком)

Хук `stop-gate.js` не даёт закончить сессию, если код менялся, а `/code-review`
в этой сессии не запускался. Напоминает один раз, дальше решение за тобой.
Настройки не требует.

## 2. Цикл по срезам dev-build

Состояние цикла — файл `docs/dev/slices.json` от `dev-build`, не переписка и
не память сессии. Нет файла — цикл строить не из чего, сначала `dev-build`.

1. Прочитать `slices.json`. Взять первый срез со `status: pending` или
   `in_progress` (по порядку, с учётом `depends_on` — зависимость должна
   быть `done`).
2. Прогнать через `loop-build`: написать красный тест, реализовать, дойти
   до `green_check` среза.
3. Чек зелёный — записать в файл `status: done` для этого среза, перейти к
   следующему `pending`. Не начинать следующий, пока текущий не `done` в
   файле — не на словах.
4. Все срезы `done` — весь список отдать на `/code-review`.

Условие остановки — команда, а не ощущение: `green_check` конкретного среза
выходит с нужным результатом, и в файле для него стоит `done`. Второй заход
после перерыва начинается с чтения файла, не с нуля.

Модель, эффорт для каждого прохода — через `model-route`, правило из
`loop-build` действует и здесь: спросить перед запуском, не решать за
владельца.

### Без присмотра — `/goal` поверх, условие пишется буквально

Владелец не будет стоять над циклом каждый проход — не просто запускай
`loop-build`, собери `/goal` по его формату (`reference/goal.md`), условие
читается прямо из `slices.json`, не с ощущения:

```
Условие: все срезы в docs/dev/slices.json имеют status "done",
верифицировано командой jq '[.[] | select(.status != "done")] | length'
по файлу — вывод 0. Не менять status на "done" в файле, не прогнав
green_check среза. Стоп после <N> ходов, N = число срезов × 3.
Запусти: /goal <текст условия целиком>
```

Показать эстимейт и получить «да», как того требует `loop-build`, прежде
чем набирать `/goal` — этот блок не набирает команду за владельца.

## Границы

- Цикл не удаляет и не переписывает файлы без подтверждения.
- Гейт только напоминает, не блокирует навсегда — обходится осознанно.
- Не строить цикл на непроверяемом условии («пока код не станет лучше»).

## Соседи

Нарезка на срезы — `dev-build`. Механизм самого цикла — `loop-build`. Оба
`dev-loop` и `sec-loop` ставят Stop-хук — если оба блока в проекте, при
выходе будет два напоминания подряд (аудит и ревью), это не конфликт, просто
два разных вопроса.
