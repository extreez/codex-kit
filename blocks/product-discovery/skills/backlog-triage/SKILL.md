# Приоритизация и триаж

3 шаблона из `pm-skills` (phuryn) — разные объекты ранжирования, не
альтернативы друг другу. Файлы в `templates/` дословно на английском,
атрибуция в начале каждого.

## Какой шаблон когда

| Запрос пользователя | Файл | Что ранжирует |
|---|---|---|
| «что тестировать первым» | `templates/prioritize-assumptions.md` | Список допущений (из `discovery-cycle`) → матрица Impact × Risk, эксперимент на каждое допущение |
| «расставь приоритеты в бэклоге» | `templates/prioritize-features.md` | Список идей фич → impact/effort/risk/strategic fit, топ-5 с обоснованием |
| «разбери эти заявки от клиентов» | `templates/analyze-feature-requests.md` | Сырые заявки клиентов → темы, частота, соответствие стратегии |

## Как выбирать

Вход у трёх шаблонов разный: допущения приходят из `discovery-cycle`,
идеи фич — из бэклога или тоже из `discovery-cycle`, заявки клиентов —
сырые данные от саппорта/продаж. Не путать вход одного шаблона с
входом другого.

`analyze-feature-requests` обычно идёт первым в цепочке (сырые заявки
→ темы), `prioritize-features` — вторым (темы/идеи → топ-5). Если
пользователь дал сразу сырые заявки и просит топ-5 — сначала прогнать
через `analyze-feature-requests`, потом через `prioritize-features`,
не пытаться сделать один шаг вместо двух.

Для готового справочника по 9 общим фреймворкам приоритизации
(RICE/ICE/Kano/MoSCoW) — см. `product-execution/planning-docs`, не
дублировать здесь.
