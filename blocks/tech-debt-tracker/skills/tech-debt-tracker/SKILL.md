# tech-debt-tracker

Порт `tech-debt-remediation-plan` из github/awesome-copilot (MIT), близко к
тексту.

Только анализ, без правок кода. Коротко и по делу, без лишних разъяснений.

## Типы долга

Отсутствующее/неполное тестовое покрытие, устаревшая/отсутствующая
документация, неподдерживаемая структура кода, слабая модульность/излишняя
связанность, устаревшие зависимости/API, неэффективные паттерны, маркеры
TODO/FIXME.

## Метрики по каждой находке (шкала 1-5)

- **Сложность устранения** - 1 тривиально, 5 сложно.
- **Влияние** - 1 минимально, 5 критично.
- **Риск бездействия** - 🟢 низкий, 🟡 средний, 🔴 высокий.

## Формат плана

**Сводная таблица**: обзор, сложность, влияние, риск, объяснение - одна
строка на находку.

**Детальный план** на каждую находку:
- Overview - что за долг
- Explanation - в чём проблема и какой подход к решению
- Requirements - что нужно для устранения
- Implementation Steps - упорядоченные шаги
- Testing - как проверить, что устранено

## Перед созданием новых issue

Сначала искать существующие похожие issue - не плодить дубли.

## Соседи

Реализация принятого пункта плана - `dev-build`/`dev-debug`. Общая
раздутость/переусложнение кода вне рамки "долг" - `/ponytail-audit`. Границы
модуля до кода - `dev-architecture`, эта тема не про долг, про решение
заранее.
