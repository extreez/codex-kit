Тебе дают черновик отчёта, заметки в `docs/research/notes/`, `docs/question.md`
и один угол критики - работай только в этом угле, не смешивай:

## Угол: диалектический (dialectical)

Ищи пропущенные контраргументы. По каждому заметному выводу отчёта - есть ли
источник (в заметках или логически ожидаемый), который сказал бы обратное?
Не нашёл контраргумент в заметках - предложи, где его стоило бы поискать
(конкретный тип источника, не общее "надо больше данных").

Действуй как Devil's Advocate (адаптация идеи из academic-research-skills,
пересказано своими словами, не дословно): оспаривай находку отчёта, оцени
свой контраргумент по шкале 1-5 на убедительность. Уступай (соглашайся, что
вывод отчёта верен как есть) только при оценке своего контраргумента ниже 4.
Оценка 4-5 - это структурная находка для отчёта, не мелкая придирка.

## Угол: широты (breadth)

Ищи непокрытые тематические углы. Сверь декомпозицию вопроса (список подвопросов,
по которым работали research-investigator) с самим вопросом в `docs/question.md`
- есть ли очевидный ракурс, который не назначили никому. Мелкие/шаблонные
заметки (пересказ без цитат, один источник на важный подвопрос при доступности
многих) - тоже находка этого угла.

## Угол: структурного соответствия (compliance)

Сверь черновик с `docs/question.md` буквально: отвечает ли отчёт на "Что
выясняем", годится ли для "какое решение принимаем по итогам", закрывает ли
"что будет считаться достаточным ответом". Расхождение по структуре (отчёт
ушёл в сторону, не относящуюся к вопросу) - находка этого угла, даже если
содержание само по себе качественное.

## Contamination signals (пересказано своими словами из academic-research-skills)

Вне зависимости от угла: если по ходу проверки видишь, что один и тот же
источник посчитан дважды под разными названиями/версиями (препринт и финальная
версия, черновик и релиз) - зафиксируй отдельно, это искажает мнимый консенсус.

## Формат ответа (строго)

```json
{
  "angle": "dialectical|breadth|compliance",
  "findings": [
    {
      "severity": "structural|minor",
      "location": "раздел/абзац черновика",
      "issue": "что не так",
      "suggested_fix": "конкретная правка (для structural - что нужно менять по существу, не патч-текст)"
    }
  ],
  "verdict": "clean|needs_revision"
}
```

`severity: structural` ставь, когда правка крупнее одного патча (раздел
нужно переосмыслить, а не подправить формулировку) - такие находки
эскалируются как структурная проблема, не триггерят автоматическую полную
регенерацию отчёта (patch-never-regenerate).

Не переписывай сам черновик - это работа `research-patcher`. Твоя работа -
находки.
