# Component Annotation (uSpec-семейство)

Четыре скилла из одного семейства (адаптированы из uSpec, Ian Guisard, MIT
license), у них общий контракт и общий guard-преамбл. Этот файл описывает
общее один раз; конкретные шаги, скрипты Plugin API и таблицы данных — в
отдельных файлах рядом, читай нужный целиком перед запуском:

| Запрос пользователя | Файл | Что строит |
|---|---|---|
| свойства, варианты, boolean-переключатели, variable modes | `property.md` | по exhibit'у на каждую ось/toggle/sub-component |
| цвета, токены, fill/stroke/effect по состояниям | `color.md` | таблицы token/style по вариантам и состояниям |
| API для разработчика, примеры использования | `api.md` | главная таблица + таблицы по sub-component + live-примеры |
| анатомия, нумерованные маркеры на превью | `anatomy.md` | composition-секция + per-child секции |

Открой соответствующий файл и следуй его шагам от начала до конца — там же
конкретные `evaluate_script`-скрипты с точными плейсхолдерами
`__UPPER_SNAKE__`. Каждый файл сохранён в оригинале (английский, дословно) —
не переведено, см. [`../README.md`](../README.md) за общим правилом.

## Общий контракт (все 4 файла)

- **Run, don't edit.** Это инструкции к выполнению, не документ для
  редактирования. Никогда не редактировать содержимое скилла посреди
  прогона.
- **Никогда не паузить** ради подтверждения. При неоднозначности выбрать
  наиболее защитимый вариант и отметить это в финальной сводке.
- **Единственная легальная остановка** — Step 1 (fail-fast при невалидном
  выделении: ничего не выбрано, мульти-селект, обычный фрейм/группа/секция/
  текст вместо компонента).

## Read-only invariant (общий для всех четырёх)

Документируемый компонент **read-only** — сам выбранный компонент, его сет,
варианты, sub-компоненты, их главные компоненты и любой библиотечный ассет.
Структура, свойства, позиция, имя, видимость, текст, заливки, variable
modes — всё неприкасаемо. Корректная аннотация поверх изменённого исходного
компонента = проваленный прогон.

**Writable scope, исчерпывающе:** аннотационный фрейм (создаётся в Step
7/8, в зависимости от файла) и его потомки, плюс инстансы, которые создают
сами эти скрипты. Никогда не сам target, никогда не страница.

Никогда `appendChild`/`insertChild`/`remove`/`clone`/`setProperties`/
`setVariantProperties`/`detachInstance`/`swapComponent`/`set`+
`clearExplicitVariableModeForCollection`/`setBoundVariable`/`resize()`, и
никогда не писать `name`/`x`/`y`/`visible`/`characters`/`fills`/`strokes`/
`layoutMode` на target, его предках или потомках. Если шагу кажется, что
это нужно — шаг неверный, пропустить и отметить в финальной сводке.

## Guard-преамбл (общий JS-паттерн)

Каждый файл открывается своей версией этого паттерна — переменные `_F`
(id аннотационного фрейма) и `_TMP` (реестр созданных инстансов), функции
`SAFE`/`ADOPT`/`NI`/`SWEEP` — они и есть техническое воплощение read-only
invariant выше: `SAFE` отказывается писать за пределы аннотационного
фрейма, `ADOPT` отказывается затащить внутрь уже существующий узел (что
утащило бы вариант из сета пользователя), `NI` — единственный конструктор
инстансов (регистрирует их в `_TMP`), `SWEEP` подчищает всё
незарегистрированное, что осталось на странице после throw. Копировать этот
паттерн в новый файл не нужно — он уже в начале `property.md`/`color.md`/
`api.md`/`anatomy.md`, вставляется перед каждым write-скриптом дословно, с
подстановкой `__FRAME_ID__`.

## Инструменты и лимиты

`use_figma`/`evaluate_script` официального Figma MCP (плагин `figma`, см.
блок `figma-mcp`). Прогон полной аннотации (все exhibit'ы + summary) может
занять десятки вызовов инструмента на сложном компоненте — на
Starter/View/Collab-сиденье (лимит 6 вызовов/месяц) выбьется мгновенно, см.
предупреждение в `figma-mcp`.

## Шаблон (uSpec Community file)

Все четыре скилла тянут визуальный шаблон из одного источника: uSpec
Template (https://www.figma.com/community/file/1603925462078533207/uspec-template)
— продублировать файл, опубликовать как библиотеку, вставить нужный
component key (`PROPERTY_TEMPLATE_KEY`/`COLOR_TEMPLATE_KEY`/
`API_TEMPLATE_KEY`/`ANATOMY_TEMPLATE_KEY`) в Configuration соответствующего
файла. Без ключа — трёхуровневый fallback (ключ → локальный компонент с
нужным именем в файле пользователя → построить scaffold с нуля), описан в
каждом файле отдельно.
