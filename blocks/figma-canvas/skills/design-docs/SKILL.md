# Design System Docs & Generation

Пять разных скиллов под одной темой «дизайн-система в Figma». Они решают
разные задачи — выбирай файл по формулировке запроса, не запускай два токен-
ориентированных скилла подряд на одном файле без причины (см. предупреждение
ниже).

| Запрос пользователя | Файл | Что делает |
|---|---|---|
| «сделай handoff-кадр для этого компонента» (Minimal/Brutalist/Card) | `component-handoff.md` | 9-секционный dev-handoff фрейм из одного выбранного COMPONENT/COMPONENT_SET |
| «задокументируй существующую дизайн-систему» | `foundations-documentation.md` | таблицы по уже существующим Variables/Styles — ничего не создаёт, только читает и оформляет |
| «построй библиотеку переменных/токенов с нуля» | `variable-library.md` | 3-уровневая архитектура brand→alias→mapped, генерирует 13-ступенчатые цветовые рампы из hex-кодов пользователя |
| «сгенерируй простую дизайн-систему из этих слоёв» | `design-system-gen.md` | компоненты (кнопки/инпуты/модалки) + 2-уровневые токены, извлекая шрифты/цвета из выделенных слоёв |
| «сделай типографическую шкалу из этого текста» | `type-scale.md` | серия вопросов (P1-P6) → расчёт 12 соотношений/4 пресетов/grid-snap/split-scale → specimen-таблица на холсте в 6 проходов → опционально FLOAT-переменные |

## ⚠ Пересечение variable-library.md и design-system-gen.md — не запускать оба на одном файле подряд

Оба создают токен-коллекции, но разной архитектуры:

- `variable-library.md` строит строгую 3-уровневую систему UI Collective
  (`brand`/`alias`/`mapped`, 152 mapped-токена, точные имена и scopes) и
  **сам себя блокирует**, если в файле уже есть коллекция `brand`/`alias`/
  `mapped` или любая коллекция с >~20 переменных — он проверяет это в Step 0
  и отказывается работать поверх существующей системы.
- `design-system-gen.md` строит простой 2-уровневый набор (примитивы →
  семантика) и **такой проверки не делает** — если запустить его после
  `variable-library.md` на том же файле, он создаст вторую, несовместимую
  систему токенов поверх первой, с дублирующимися/конфликтующими именами.

Порядок, если нужны оба: сначала `variable-library.md` (он сам откажется
работать повторно), либо выбрать один подход на проект и не смешивать —
подробнее см. `CONFLICTS.md` в корне caталога `codex-kit`.

`foundations-documentation.md` конфликта с ними не создаёт — он read-only
относительно исходных Variables/Styles и просто задокументирует то, что
получилось после любого из двух генераторов выше.

## Общее для всех четырёх

- Никогда не менять исходные пользовательские страницы/компоненты вне
  создаваемой документации/системы (кроме `variable-library.md`, который
  по своей природе создаёт новые Variable Collections — это его прямая
  задача, не побочный эффект).
- Загружать шрифты (`figma.loadFontAsync`) до создания любого текста.
- Открой нужный файл целиком и следуй его шагам — там же конкретные
  `evaluate_script`-скрипты, guard-функции и таблицы значений, сохранённые
  дословно из оригинала.
