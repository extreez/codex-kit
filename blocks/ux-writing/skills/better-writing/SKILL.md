# Копирайтинг интерфейса

Ясное и краткое лучше умного; последовательное лучше разнообразного.
Лучшее сообщение об ошибке — переработанное взаимодействие, где ошибка не
может случиться.

Полный текст (таблицы good/bad, формат отчёта) —
[better-writing.md](better-writing.md), дословно на английском.

## Разведка перед правкой

Читать голос продукта и терминологию рядом, прежде чем писать или
ревьюить. Осознанный брендовый голос — не дефект; поднимать отклонение от
простого языка только когда оно создаёт несогласованность, двусмысленность,
риск перевода или тон не по ставкам момента.

## Один голос, гибкий тон

| Контекст | Тон |
| --- | --- |
| Успех, онбординг, пустые состояния | Тёплый, может быть лёгким |
| Рутинные действия, настройки | Нейтральный, минимальный |
| Ошибки, деструктивные подтверждения | Спокойный, простой, без игривости |
| Потеря данных, безопасность | Серьёзный, явный |

Термины держать согласованными: если в меню "Архив", в тосте не должно
стать "Переместить в хранилище".

## Кнопки — глагол первым

Лейбл кнопки начинается с глагола, называющего действие: "Отправить",
"Сохранить черновик", "Удалить проект". Никогда "ОК!", "Поехали!", голое
"Да"/"Нет" на значимом действии. Подтверждение деструктивного действия
повторяет последствие: "Удалить этот проект?" → кнопки `Удалить проект` /
`Отмена`.

## Ошибки — рядом с полем, с инструкцией фикса

| Плохо | Хорошо |
| --- | --- |
| Пароль слишком короткий | Выберите пароль минимум из 8 символов |
| Неверное имя | Используйте только буквы для имени |
| Упс! Что-то пошло не так. | Не удалось сохранить. Проверьте соединение и попробуйте снова. |

Без обвинения, без "упс", без восклицательных знаков. Формулировать
позитивно ("используйте только буквы", не "не используйте цифры") и
показывать до ошибки, не после. Если одна и та же ошибка повторяется —
переработать взаимодействие, не переформулировать текст.

## Пустые состояния указывают вперёд

Что это за место, как его заполнить, одно ясное следующее действие.
Никогда не хранить в пустом состоянии постоянную информацию — она исчезнет
в момент появления контента.

## Одна политика capitalization

Sentence case — более безопасный дефолт: спокойнее, без по-словных
правил для запоминания, чище локализуется.

## Проверяемый результат (для /loop-build)

Часть правил механически проверяема: verb-first кнопки (первое слово —
глагол), единая capitalization-политика (grep на смешанный Title Case/
sentence case в одном UI), ошибка рядом с полем, а не только в тосте
(DOM-проверка позиции). Голос/тон в целом — вердикт verifier-subagent,
не команда.

## Ревью текста по всему продукту — распараллелить

Просят вычитать копирайт сразу по многим экранам/флоу — subagent на
экран/флоу (не на отдельный текстовый элемент, слишком мелко), каждый
сверяет свой участок с правилами голоса/тона, сводка расхождений в
конце — единый голос всё равно проверяется одним финальным чтением
сводки, не по частям.
