# rabbithole

Своего MCP-сервера этот блок не заводит и своей методологии не синтезирует —
`rabbithole` (shlokkhemani/rabbithole, MIT) ставится как есть, по прямому
решению пользователя. Сервер держит документ открытым и ждёт вопросов: каждый
новый вопрос порождает следующий узел ветвящегося холста, не переписывает
существующий.

## Установка

```bash
claude mcp add rabbithole -- npx -y github:shlokkhemani/rabbithole
```

Требования: Node.js 18+, авторизованный Codex.

Опционально — куда складывать документы (по умолчанию `~/.rabbithole/`):

```bash
claude mcp add rabbithole --env RABBITHOLE_DIR=/путь/к/папке -- npx -y github:shlokkhemani/rabbithole
```

Хранилище локальное, без облачной синхронизации.

## Когда использовать вместо `research-deep`

Разные задачи, не конкуренты. `research-deep` — линейный отчёт с проверенными
цитатами под конкретный вопрос из `docs/question.md`, готовится для решения.
`rabbithole` — открытый холст для разведочного «покопаться в теме», без
обязательства дойти до отчёта; узлы холста можно потом передать в
`research-deep` как отправную точку декомпозиции, если разведка на холсте
нашла, во что углубляться.

## Проверяемый результат (для /loop-build)

Готово — когда MCP отвечает: список инструментов содержит инструменты
rabbithole, открытие документа не даёт ошибку подключения.
