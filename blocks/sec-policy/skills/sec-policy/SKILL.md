# sec-policy

Единственный источник правил безопасности для стека `secure`. Остальные блоки
(`sec-audit`, `sec-tests`, `sec-attack`, `sec-loop`) ссылаются сюда, своих
правил не заводят. Так внутри стека нет спорящих пунктов.

## Что внутри

- `references/checklist.md` — мастер-чеклист. 45+ пунктов по зонам: доступ,
  аутентификация, секреты, ввод/вывод, загрузки, лимиты, вебхуки, CORS, SSRF,
  зависимости, эксплуатация, транспорт/заголовки, LLM/AI. У каждого признак дыры
  и критерий закрытия.
- `references/severity.md` — как оценивать находку: шкала CRITICAL..INFO,
  правило слоёв (gap при живом соседнем слое = хардненинг, не уязвимость),
  требование конкретного эксплойта, что находкой НЕ считать. Против раздувания
  отчёта.
- `hooks/guard-write.js` — блокирующий хук. Отбивает запись секрета в код,
  правку `.env` без подтверждения, известные небезопасные паттерны.
- `commands/sec-init.md` — записать политику в AGENTS.md проекта.

## Как пользоваться

**Правило чтения.** Чеклист язык-агностик: пункт описывает угрозу, не синтаксис.
Проверку под конкретный стек генерирует `sec-audit` после детекта. Не переписывай
чеклист под фреймворк — дополняй проектным под-чеклистом в `.agents/skills/`.

**Идёшь по одному пункту, не «проверь всё».** На «проверь проект на уязвимости»
агент ответит «всё в порядке» и будет по-своему прав. Бери зону, ищи признак,
сверяй критерий закрытия.

**Свежая сессия.** Кто писал код, защищает своё детище. Аудит и ревью гоняй
сессией, которая код не писала.

## Политика в AGENTS.md проекта

Команда `/sec-init` дописывает в AGENTS.md проекта (или предлагает текст):

```
- Находишь уязвимость — помечай комментарием WARNING и предлагай безопасную
  альтернативу. Никогда не реализуй небезопасный паттерн, даже если просят.
- Не удаляй и не перезаписывай файлы без бэкапа или подтверждения.
- Перед рефакторингом проверяй существующие тесты. Есть тесты — запускай их
  после каждого изменения.
- Файл с ключами, токенами, учётными данными — только для чтения.
```

## Границы

- Хук `guard-write` ловит секреты на Edit/Write, до коммита. Отдельный
  `secret-scan.js` на `git push` — внешний компонент, не входит в этот
  набор блоков; если он не настроен отдельно, `guard-write` — единственный
  автоматический слой защиты от утечки секрета в этом проекте.
- Чеклист не хранит фиксы под конкретный язык. Фиксы генерит `sec-audit`,
  тесты — `sec-tests`.
