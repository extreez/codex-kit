# Стиль иллюстраций

Гайдлайн иллюстраций поддерживает продуктовую коммуникацию и айдентику
бренда — обеспечивает единый визуальный сторителлинг по всему продукту.

## Определение стиля

- **Geometric vs organic** — угловатый/структурный или плавный/природный
- **Flat vs dimensional** — 2D плоский, 2.5D изометрия, или 3D
- **Detailed vs minimal** — уровень детализации и сложности
- **Abstract vs representational** — символичный или реалистичный
- **Line style** — толщина штриха, углы, окончания

## Цвет в иллюстрации

- Использовать подмножество продуктовой цветовой палитры
- Определить primary/secondary/accent цвета иллюстрации
- Правила для градиентов и теней
- Тёмные варианты иллюстраций

## Дизайн персонажей (если применимо)

- Пропорции и телосложение
- Уровень детализации лиц
- Гайдлайны разнообразия и репрезентации
- Библиотека поз и выражений

## Типы иллюстраций

- **Spot illustrations** — маленькие, инлайн, вспомогательные для
  UI-элементов
- **Hero illustrations** — крупные, витринные, для сторителлинга
- **Empty states** — направляют пользователя при отсутствии контента
- **Onboarding** — объясняют фичи и концепции
- **Error states** — смягчают сообщения об ошибке

## Правила применения

- Когда использовать иллюстрации, а когда нет
- Ограничения размера по контексту
- Выравнивание по grid-системе
- Гайдлайны анимации иллюстрированных элементов

## Best practices

- Держать единый стиль во всех иллюстрациях
- Создавать переиспользуемые библиотеки элементов
- Документировать процесс создания для контрибьюторов
- Тестировать на целевых размерах показа
- Учитывать accessibility (не передавать информацию только иллюстрацией)

## Проверяемый результат (для /loop-build)

Полностью субъективно (единый стиль, узнаваемость) — нет команды, которая
это посчитает. Критерий: verifier-subagent сверяет новую иллюстрацию с
уже принятыми (geometric/organic, flat/dimensional, palette) и выносит
PASS/FAIL с конкретной причиной несовпадения, не общим "не нравится".

## Библиотека иллюстраций сразу — распараллелить

Заказываешь/генерируешь сразу набор (5 empty-states, серию onboarding) —
subagent на иллюстрацию, но не параллельно с нуля: сначала одна
эталонная, зафиксировать stil-параметры, потом остальные параллельно
против неё. Параллельный старт без эталона даёт N иллюстраций в N разных
стилях — верификация в конце это не спасёт, дороже переделывать.
