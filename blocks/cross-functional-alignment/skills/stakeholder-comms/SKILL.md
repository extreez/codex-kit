# Коммуникация со стейкхолдерами

5 инструментов из `Owl-Listener/ux-pgm-skills`, обобщены от UX-
программы до любого проекта. Файлы в `templates/` дословно на
английском (кроме `stakeholder-map.md` — синтез двух источников, см.
файл), атрибуция в начале каждого.

## Какой инструмент когда

| Запрос пользователя | Файл | Что даёт |
|---|---|---|
| «построй карту стейкхолдеров» | `templates/stakeholder-map.md` | Power/interest/stance/currency-grid → коммуникационный план по квадрантам, что двигает скептиков |
| «спроектируй workshop для алайнмента» | `templates/alignment-workshop.md` | Один outcome на сессию, pre-read, divergent→convergent активности, письменные commitments в конце |
| «пропиши план эскалации» | `templates/escalation-plan.md` | Триггеры, путь по людям, SLA, формат (issue/impact/options/recommendation/ask) |
| «напиши апдейт для руководства» | `templates/executive-update.md` | So what / где мы / один риск / один ask — не больше одного экрана |
| «сделай статус-репорт по программе» | `templates/status-report.md` | Headline (on track/at risk/off track) + RAG + прогресс по исходам + риски + конкретные просьбы с датой |

## Как выбирать

`stakeholder-map` — точка входа (кого и как вовлекать), остальные
четыре — конкретные форматы коммуникации по ходу программы.
`status-report` — регулярный (по кадансу), `executive-update` —
разовый под конкретное решение, `escalation-plan` — заготовка на
случай, когда что-то пошло не так (написать до того, как понадобится,
не в момент паники).

`executive-update` и `status-report` не заменяют друг друга: update —
для руководителя с 30 секундами и одним asks, report — для более
широкой аудитории с прогрессом и рисками целиком. Не сжимать
status-report до формата executive-update без явного запроса.

Плохая эскалация — это молчание до дедлайна. Правило источника: рано —
сила, не слабость, эскалировать решение, не вину, всегда с опцией и
рекомендацией, не просто с проблемой.

Для карты зависимостей и capacity команды (не про людей-стейкхолдеров,
про сам объём работы) — см. `program-delivery/program-planning`.
