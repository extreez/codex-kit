# Community-маркетинг

## 5 моделей сообществ

| Модель | Ядро активности | Подходит когда |
|---|---|---|
| Support-driven | Пользователи помогают друг другу с вопросами | Продукт достаточно сложный, чтобы у пользователей были вопросы, и достаточно широкий, чтобы паттерны вопросов повторялись |
| Product-development | Обратная связь по фичам, бета-тестирование, roadmap-обсуждение | Продукт в активной разработке, есть что обсуждать регулярно |
| Education | Обучающий контент, воркшопы, сертификация | Продукт требует навыка для полного использования (не просто «нажми кнопку») |
| Founder-led | Личный бренд основателя как центр притяжения | Ранняя стадия, founder готов инвестировать личное время и присутствие |
| Networking | Участники ценят связь друг с другом, не только с продуктом | Продукт обслуживает профессиональную нишу, где нетворкинг сам по себе ценность |

Выбор модели — не «какая моднее», а какая совпадает с реальным
поведением аудитории (секция 2, 13 контекста продукт-маркетинга —
где аудитория уже собирается и зачем).

## Community flywheel

```
Участник получает ценность (ответ/связь/знание)
  → делится своим опытом/помогает другому
    → новый участник видит активность и присоединяется
      → цикл повторяется
```

Flywheel не раскручивается сам — на старте (пока участников мало)
нужен явный «сеятель» активности (обычно команда/founder), иначе
пустое сообщество не создаёт ощущение жизни, и цикл не запускается.

## Метрики здоровья

| Метрика | Ориентир |
|---|---|
| DAU/MAU | **>20%** — признак здорового активного сообщества, ниже — сообщество существует, но не вовлечено ежедневно |
| Time to first response | Как быстро новый вопрос получает ответ (от участника или команды) — долгое молчание убивает доверие к активности площадки |
| Ratio участников-создателей к участникам-читателям | Здоровое сообщество не требует 50/50 — 90/10 (10% создают контент/отвечают, 90% читают) нормально, но 10% должны быть реальными, не только командой |
| Retention участников | Доля вернувшихся через 30/60/90 дней после присоединения |

## Частые ошибки

- Запуск community без модели, ясной команде — «просто заведём
  Discord» без понимания, вокруг какой активности он строится.
- Отсутствие сеятеля активности на старте — пустой канал отпугивает
  новых участников больше, чем его отсутствие вообще.
- Метрика успеха — только число участников, без DAU/MAU — большое,
  но неактивное сообщество не даёт retention/growth эффекта.
