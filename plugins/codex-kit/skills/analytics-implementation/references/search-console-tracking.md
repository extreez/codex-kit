# Search Console и рэнк-трекинг

> Добавлено при сборке стека `seo` (не из исходного набора router-файлов
> analytics-implementation) — собственный синтез, не порт стороннего
> источника. Заполняет пробел: у блока `metrics` не было методологии под
> Google Search Console/рэнк-трекинг, узкую SEO-аналитику, которая не
> дублирует более широкий `product-metrics`/`attribution`.

## Зачем отдельно от GA4

GA4 меряет поведение уже пришедших посетителей. Search Console меряет то,
что происходит до клика — как сайт показывается в выдаче: по каким
запросам, с какой позицией, с каким CTR, попадает ли страница в индекс
вообще. Это данные, которых нет ни в одном другом источнике — Google не
делится сырыми позициями через GA4.

## Настройка

1. Подтвердить владение доменом в Search Console (DNS-запись или
   HTML-файл/тег — DNS предпочтительнее, покрывает все поддомены и
   протоколы разом).
2. Отправить `sitemap.xml` через раздел Sitemaps (не обязательно для
   индексации, но ускоряет обнаружение новых страниц и даёт отчёт
   покрытия sitemap отдельно от общего покрытия сайта).
3. Связать с GA4 (Admin → Search Console links) — тогда данные о запросах
   доступны и в отчётах GA4, не только в самом Search Console.

## Что снимать регулярно

| Отчёт | Что даёт | На что смотреть |
|---|---|---|
| Performance (Efficiency) | Запросы, клики, показы, CTR, позиция | Запросы с высокими показами и низким CTR — заголовок/сниппет не мотивирует клик, даже если позиция хорошая |
| Coverage / Pages | Какие страницы проиндексированы, какие исключены и почему | Исключённые страницы, которые должны быть в индексе — прямой вход в `seo-audit` слой Indexability |
| Core Web Vitals | Полевые данные (CrUX), не лабораторные | Для root-cause разбора — см. `seo-audit`, слой Signals, SG-6/SG-7/SG-8 |
| Links | Внешние и внутренние ссылки, как их видит Google | Сверка с `seo-offpage` — расхождение между тем, что видит Google, и тем, что нашёл собственный аудит перелинковки |
| Mobile Usability (если ещё показывается) | Проблемы мобильной версии | Устаревающий отчёт в интерфейсе GSC, проверить актуальность на момент использования |

## Рэнк-трекинг — что это и зачем отдельно от Search Console

Search Console даёт позицию с задержкой (данные за последние ~16 месяцев,
не в реальном времени, усреднённая позиция по дню) и не различает
устройство/локацию так гибко, как выделенный рэнк-трекер. Для регулярного
отслеживания топ-N позиций по приоритетным ключам (см. кластеры в
`seo-content`) — отдельный рэнк-трекинг инструмент даёт более частые
срезы и разбивку по геолокации/устройству.

Self-hosted вариант без подписки на SaaS — см.
`library/seo-crawler-tool/README.md` (SerpBear).

## Формат отчёта

Добавляется в тот же Tracking Plan Document, что и остальная аналитика
(см. `SKILL.md`, раздел «Формат вывода»), отдельным блоком:

```markdown
## Search Console — Overview
- Домен подтверждён: [да/нет, способ]
- Sitemap отправлен: [да/нет, дата]
- Связан с GA4: [да/нет]

## Search Console — топ находок
| Запрос | Показы | Клики | CTR | Позиция | Заметка |
```

## Смежные блоки

`seo-audit` — Coverage-отчёт GSC подтверждает или опровергает находки
слоя Indexability. `seo-content` — Performance-отчёт (запросы с высокими
показами, низким CTR) — источник для приоритизации content brief.
`attribution` — Search Console данные не заменяют модель атрибуции,
только объясняют органический канал до клика.
