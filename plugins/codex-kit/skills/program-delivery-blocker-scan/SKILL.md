Прогони один проход по скиллу `delivery-execution` в блоке
`program-delivery`, разделы `blocker-triage` и `risk-register`.

Это не одноразовый отчёт, а проверка, рассчитанная на повтор — команда
предназначена для запуска через `/loop <интервал> /blocker-scan`
(например `/loop 1d /blocker-scan`), пользователь сам выбирает
интервал под темп своей программы. Каждый запуск — снимок текущего
состояния, не накопительный отчёт.

Шаги одного прохода:

1. **Блокеры** — `templates/blocker-triage.md`. Что заблокировано,
   чем, кто владелец разблокировки, severity, возраст. Если есть
   данные о прошлом проходе (файл со снимком) — сравнить возраст
   блокеров, отдельно выделить те, что стоят дольше SLA.
2. **Риски** — `templates/risk-register.md`. Likelihood × impact,
   владелец, реакция, триггер. Отметить риски без владельца — по
   источнику это «декорация», не настоящий риск.

Вывод — короткий markdown-снимок с двумя секциями (блокеры/риски),
подходящий для быстрого чтения раз в интервал, не полный доклад.
Если данных для сравнения с прошлым проходом нет — явно сказать, что
это первый снимок, не выдумывать тренд.

Модель/эффорт не спрашивать — регулярный короткий проход без
субагентов.
