# Позиционирование и запуск

## Перед стартом

Прочитать `.agents/product-marketing.md`. Если файла нет — предложить
`product-marketing-context` этого же блока. Особенно нужны секции 6
(конкуренты) и 7 (дифференциаторы) — без них позиционирование строится
на догадках.

---

## Позиционирование по April Dunford

Пять шагов по порядку — каждый следующий зависит от предыдущего,
пропускать нельзя.

### Шаг 1. Конкурентные альтернативы

Не «прямые конкуренты» в узком смысле — то, что клиент выбрал бы, если
бы продукта не существовало. Часто это: другой инструмент,
самодельное решение (Excel/скрипт), статус-кво («ничего не делать»),
найм человека на задачу.

Вопрос: «Если бы наш продукт исчез завтра, что бы вы использовали?»

### Шаг 2. Уникальные атрибуты/возможности

Что есть у продукта, чего нет ни у одной альтернативы из шага 1.
Список фактов, не выгод — «атрибут» это то, что продукт умеет,
«выгода» появится на шаге 3.

Проверка: если конкурент тоже может это сделать — не уникально,
вычеркнуть.

### Шаг 3. Ценность уникальных атрибутов

Для каждого атрибута из шага 2 — что это даёт клиенту. Один атрибут
может давать разную ценность разным сегментам аудитории (это
подсказка к шагу 4).

Формат: «Атрибут X → значит клиент может Y → что для него важно
потому что Z».

### Шаг 4. Целевой сегмент рынка

Кто ценит эту ценность больше всех остальных — не «все, кому может
пригодиться», а сегмент, для которого шаг 3 звучит как «наконец-то»,
а не «неплохо».

Признак верного сегмента: у него есть бюджет, боль достаточно остра,
чтобы платить за решение прямо сейчас, и его легко найти/охватить
через каналы (секция 13 контекста продукт-маркетинга).

### Шаг 5. Категория рынка

В какой категории продукт хочет, чтобы его сравнивали. Готовая
категория (понятна с полуслова, но конкуренция и ожидания уже заданы
чужими лидерами) или новая категория (нет конкуренции за ум клиента,
но нужно объяснять с нуля, что это вообще такое). Выбор категории —
стратегическое решение, не терминологическое.

### Итог: positioning statement

```
Для [целевой сегмент],
которому нужно [ценность/результат],
[название продукта] — это [категория],
который [ключевой дифференциатор],
в отличие от [главная альтернатива].
```

## Positioning map (2x2)

Визуальная проверка, что позиционирование не совпадает с конкурентами.

1. Выбрать две оси, важные для целевого сегмента (не любые
   характеристики — те, за которые сегмент реально платит: например
   «простота настройки» × «глубина кастомизации», не «цвет логотипа»).
2. Разместить продукт и 3-5 конкурентов на карте по фактическому
   положению (не по желаемому).
3. Найти пустой угол, который совпадает с ценностью для целевого
   сегмента (шаг 3-4 выше) — это и есть защитимая позиция.
4. Если продукт и конкурент в одной точке карты — либо оси выбраны
   неверно (не те, что важны сегменту), либо позиционирование пока не
   дифференцирует.

## Боевая карточка (battlecard)

Формат на одного конкурента, для команды продаж/поддержки:

```markdown
# Battlecard: [Наш продукт] vs [Конкурент]

## Когда всплывает
[В каких сделках/запросах клиент упоминает этого конкурента]

## Value proposition конкурента
Promise: [что конкурент обещает]
Evidence: [чем подкрепляет]
Mechanism: [как технически/процессно достигает]
Uniqueness: [что конкурент считает своим отличием]

## Где мы выигрываем
- [дифференциатор 1 + почему это важно этому сегменту]
- [дифференциатор 2]

## Где конкурент сильнее — честно
- [где мы объективно слабее — без этого карточка бесполезна в реальной сделке]

## Возражения клиента и ответы
| Возражение | Ответ |
|---|---|
| «У них дешевле» | [...] |
| «Мы уже используем их» | [...] |

## Что не говорить
[Юридические/этические ограничения — не сравнивать ложно, не
дискредитировать необоснованно]
```

Обновлять карточку не реже раза в квартал — конкурент меняет продукт,
цену, позиционирование быстрее, чем кажется.

## GTM-запуск

### ORB-модель каналов

Каждый канал запуска относится к одной из трёх категорий:

| Категория | Что это | Пример | Свойство |
|---|---|---|---|
| **Owned** | Каналы, которые контролирует сам | email-лист, блог, продукт (in-app) | Медленно растёт, полностью контролируем, не зависит от чужих правил |
| **Rented** | Платформы с чужими правилами | соцсети, маркетплейсы, App Store | Быстрый охват, но алгоритм/правила могут смениться без предупреждения |
| **Borrowed** | Чужая аудитория на разовой основе | партнёрства, PR, гостевые посты, инфлюенсеры | Разовый всплеск, не накопительный актив |

Хороший план запуска использует все три, не полагается на один канал
целиком (особенно rented — алгоритмическая зависимость).

### SLC вместо MVP

**MVP** (Minimum Viable Product) — минимум, который технически
работает, часто отталкивает первых пользователей неполнотой.

**SLC** (Simple, Lovable, Complete) — то же ограничение по объёму
фич, но с требованием: то немногое, что есть, работает полностью и
вызывает симпатию, а не терпимость. Гейт готовности к запуску: если
хоть один критерий (Simple/Lovable/Complete) не выполнен — рано
запускать этот объём фич, либо сузить scope, либо отложить.

### Три фазы запуска

| Фаза | Цель | Кто видит |
|---|---|---|
| **Pre-launch** | Собрать waitlist, тизеры, партнёрские анонсы, подготовить материалы (Owned/Borrowed) | Узкий круг, не публично |
| **Launch** | Максимальный единовременный охват — день запуска | Публично, все каналы разом |
| **Post-launch** | Удержать momentum: контент по фидбеку первых пользователей, кейсы, итерация на возражениях | Публично, длинный хвост |

### Чек-лист дня запуска

- [ ] Anchor-контент готов (страница продукта/лендинг, объясняющая
      value proposition из positioning statement)
- [ ] Материалы под каждый канал ORB подготовлены заранее, не пишутся
      в день запуска
- [ ] Команда поддержки/продаж знает battlecard и топ-5 возражений
- [ ] Есть план на «запуск не выстрелил» — что делать, если охват
      ниже ожидаемого (не паниковать, разобрать причину: канал,
      сообщение или продукт)
- [ ] Метрика успеха определена заранее (не «посмотрим, как пойдёт»)

## Частые ошибки

- Позиционирование выбирается по вкусу команды, а не по шагам 1-4 —
  начинается с «мы хотим звучать премиально», а не с сегмента.
- Positioning map строится по осям, которые важны команде, а не
  сегменту (например «технологичность», когда сегмент платит за
  «скорость внедрения»).
- Battlecard хвалит только себя — без честной секции «где конкурент
  сильнее» карточка ломается при первом же реальном возражении.
- Запуск ставит всё на один rented-канал (обычно один соцсеть-алгоритм)
  без owned-подушки на случай изменения правил площадки.

## Вопросы для уточнения задачи

1. Это позиционирование нового продукта, ре-позиционирование
   существующего, или разовая боевая карточка на одного конкурента?
2. Есть ли уже собранный профиль конкурента (`ux-research/
   competitor-profiling`) или нужно опираться на общее знание рынка?
3. Это подготовка к запуску — если да, какая фаза (pre/launch/post)?
4. Кто аудитория итогового документа — продажи (battlecard),
   маркетинг (positioning statement для копирайтинга), руководство
   (GTM-план)?
