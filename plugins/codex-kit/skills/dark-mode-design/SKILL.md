# Тёмная тема

Тёмная тема — не инверсия цвета, а переосмысление поверхностей.

## Базовые принципы

- Снижать общую светимость, чтобы уменьшить усталость глаз
- Elevation (приподнятость) — через более светлые оттенки, не через тени
  (в тёмной теме тени часто не видны)
- Десатурировать яркие цвета для тёмного фона
- Держать достаточный контраст для читаемости

## Иерархия поверхностей (тёмная тема)

- **Background** — самый тёмный (например `#121212`)
- **Surface 1** — чуть светлее (приподнятые карточки)
- **Surface 2** — светлее (модалки, дропдауны)
- **Surface 3** — самый светлый из тёмных (тултипы, меню)

## Адаптация цвета

- Первичные цвета — снизить насыщенность на 10-20%
- Error/warning — подстроить под контраст тёмного фона
- Текст — не чистый белый (`#FFFFFF`), а off-white (`#E0E0E0`)
- Границы — тонкие, низкой прозрачности, белые

## Изображения и медиа

- Рассмотреть лёгкое затемнение картинок
- Предусмотреть тёмные варианты иллюстраций
- Логотипам может понадобиться light-on-dark версия
- Избегать крупных ярких областей в изображениях

## Accessibility в тёмной теме

- Минимум 4.5:1 контраста для основного текста
- Тестировать со screen reader (объявление смены режима)
- Уважать `prefers-color-scheme`
- Давать ручной переключатель наряду с авто-определением

## Best practices

- Не просто инвертировать — переосмыслять поверхности продуманно
- Тестировать в реальных тёмных условиях
- Проверять каждый компонент в тёмной теме
- Плавные переходы между режимами
- Семантические токены для беспроблемного переключения

## Проверяемый результат (для /loop-build)

Контраст — единственная численно проверяемая часть здесь (остальное —
вкус: подобрана ли поверхность, не съехала ли иерархия). Используй
`check_contrast.py` из `web-taste/gate-check/scripts/` на все текстовые/
интерактивные пары тёмной темы: готово — когда скрипт не находит пар
ниже 4.5:1 (обычный текст) / 3:1 (крупный текст, UI-компоненты).
Остальное (переосмысленные поверхности, а не просто инверсия) —
вердикт verifier-subagent по чеклисту Best practices выше, не команда.

## Несколько компонентов сразу — распараллелить

Адаптируешь под тёмную тему сразу много компонентов/экранов — раздай по
subagent на компонент, каждый сверяет свою иерархию поверхностей и гонит
`check_contrast.py` по своим парам. Общий риск — разные компоненты могут
выбрать разные оттенки для одной и той же Surface-роли; после параллельного
прохода сверь итоговую палитру одним чтением, не по отдельности.
