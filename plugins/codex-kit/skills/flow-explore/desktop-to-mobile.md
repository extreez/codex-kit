# Desktop to Mobile

Создаёт мобильную версию выбранного десктоп-фрейма. Мобильная версия должна
ощущаться нативно спроектированной под мобильный — не сжатым десктопом.
Сохранить бренд, контент и визуальный язык в точности; трансформировать
только структуру, размеры и паттерны взаимодействия.

## Настройка холста

- Целевая ширина: **390px** (iPhone 14/15 baseline). Если пользователь
  назвал другую ширину — использовать её.
- Высота: auto — растёт с контентом. Никогда не обрезать и не прятать
  контент, чтобы влезть в произвольную высоту.
- Назвать новый фрейм `[original name] — Mobile 390`.
- Разместить **120px справа** от десктоп-фрейма.
- Никогда не менять оригинальный десктоп-фрейм.

## Шаг 1 — Прочитать и картировать десктоп-фрейм

Прежде чем что-то создавать:

1. Прочитать полное дерево узлов выделения: секции, их порядок, сетки,
   компоненты, текстовые стили, значения отступов.
2. Определить типы секций (hero, nav, feature grid, pricing, testimonials,
   gallery, footer, forms, tables и т.д.).
3. Отметить систему отступов (базовая единица, паддинги секций) и
   типографическую шкалу — мобильные значения будут выведены из них, не
   изобретены.
4. Если выделение не фрейм, или это один маленький компонент, а не
   страница/экран — сказать пользователю и остановиться.

## Шаг 2 — Глобальные правила трансформации

**Лейаут**
- Многоколоночные сетки складываются в одну колонку. Порядок колонок =
  порядок чтения десктопа (слева-направо, сверху-вниз).
- Ширина контента: 390 − 2×20px боковых полей = **350px** зона контента.
  Боковой padding: 20px (или 16px, если система десктопа использует базу
  4px).
- Вертикальный padding секции: снизить десктопные значения на ~40–50%
  (например 120px → 64px, 96px → 56px, 64px → 40px). Сохранить
  пропорциональность ритма — большие десктопные отступы остаются больше
  на мобильном.
- Отступы между сложенными элементами: 16–24px из шкалы отступов
  десктопа.
- Использовать auto layout (vertical) для каждой сложенной секции, чтобы
  фрейм оставался редактируемым.

**Типографика**
- Уменьшать заголовки на ~30–40%, тело почти не трогать:
  - Десктоп 64–72 → 36–40
  - Десктоп 48–56 → 30–32
  - Десктоп 32–40 → 24–28
  - Десктоп 24 → 20
  - Body 16–18 → оставить 16 (никогда не ниже 15 для body)
  - Captions/labels → оставить, минимум 12
- Line-height: заголовки 1.1–1.2, body 1.5–1.6.
- Ничего не сокращать: сохранить весь текст. Если заголовок переносится на
  4+ строки — отметить это в финальном отчёте, а не переписывать.
- Выравнивать длинные текстовые блоки влево, даже если десктоп их
  центрирует; центр нормален для коротких hero и заголовков секций.

**Тач-таргеты**
- Каждый интерактивный элемент: минимум **44×44px** hit area.
- Кнопки: full-width (350px) для основных CTA в сложенных секциях; высота
  48–56px. Вторичные кнопки могут остаться intrinsic width.
- Соседние тап-таргеты: минимум 8px между ними.
- Ссылки внутри текста тела: оставить, но убедиться, что line-height даёт
  достаточно места для тапа.

**Изображения**
- Full-bleed изображения могут выходить край-в-край (390px); contained
  изображения остаются в зоне контента 350px.
- Сохранять пропорции; переключать широкие панорамные кропы (например
  21:9 hero) на 4:3 или 1:1 кропы с фокусом на объекте.
- Декоративные фоновые элементы, которые загромождают маленький экран:
  уменьшить или убрать, перечислить каждое удаление в финальном отчёте.

## Шаг 3 — Паттерны по типам секций

**Навигация** — десктопная горизонтальная нав → топ-бар 64px высотой: лого
слева, иконка гамбургера справа. Также создать отдельный фрейм
`[name] — Mobile Menu`, показывающий открытое состояние меню:
full-screen или dropdown со сложенными nav-ссылками, высота строки 56px
каждая. Если у десктопной нав есть заметный CTA (например "Get started") —
оставить его видимым в топ-баре рядом с гамбургером, если есть место,
иначе первым элементом в открытом меню. Если страница app-like (dashboard)
с 3–5 основными назначениями → нижний tab bar (56px, иконки + лейблы)
вместо гамбургера.

**Hero** — сложить: заголовок → подзаголовок → CTA → hero-изображение.
Если изображение — само сообщение (product shot), изображение может идти
первым. Две CTA рядом → сложить вертикально, основной сверху, отступ 12px.

**Feature grids (3–4 колонки)** — сложить в одну колонку, ИЛИ
горизонтальная swipe-карусель, если 4+ визуально насыщенных карточки. По
умолчанию — сложить. Карусель только для галерей карточек, логотипов,
отзывов. Внутренний padding карточки: снизить ~25% от десктопа.

**Logo bars / social proof** — обернуть в 2 строки, или один ряд с
горизонтальным скроллом. Уменьшить логотипы до максимальной высоты
28–32px.

**Pricing tables** — сложить планы вертикально, рекомендуемый план первым
(не посередине, как на десктопе). Если планы делят длинную сравнительную
таблицу фич → каждая карточка плана перечисляет свои фичи; убрать
сравнительную матрицу и отметить в отчёте.

**Data tables** — таблицы шире 350px: превратить каждую строку в карточку
(пары label: value стопкой), или сделать таблицу горизонтально
скроллируемой с закреплённой первой колонкой. По умолчанию: карточки для
≤6 колонок простых данных, скролл для плотных числовых таблиц.

**Forms** — все поля full-width, стопкой. Высота поля 48–56px. Лейблы над
полями, никогда только placeholder. Многоколоночные строки формы (First
name | Last name) → сложить, если оба поля не короткие (ZIP | City могут
остаться парой).

**Footer** — колонки складываются; группы ссылок становятся списками
стопкой или аккордеонами, если групп 4+. Правовая строка и соцсети —
последними.

**Sticky-элементы** — десктопный sticky sidebar CTA → sticky bottom bar на
мобильном (full-width кнопка, 16px padding, над safe area).

## Шаг 4 — Приоритизация контента

Мобильные пользователи скроллят, но внимание падает. Без удаления
контента: сохранить порядок секций десктопа, если секция не чисто
декоративный филлер перед основным CTA — в этом случае её можно сдвинуть
ниже секции CTA. Отметить любую перестановку в отчёте. Складывать длинные
FAQ-списки в аккордеоны (первый пункт может быть развёрнут). Длинные стены
отзывов → карусель по одному отзыву за раз.

## Шаг 5 — Финализация и отчёт

1. Проверить: нет горизонтального overflow нигде, весь текст читаем (body
   ≥15px), все тач-таргеты ≥44px, auto layout применён ко всем сложенным
   секциям.
2. Сдать фреймы: `— Mobile 390` и `— Mobile Menu` (плюс любые state-фреймы).
3. Отчёт в чате: какие секции трансформированы и какой паттерн для каждой;
   что удалено, обрезано, переставлено или сконвертировано (например
   "сравнительная матрица → per-card списки фич"); флаги для ручной
   проверки (заголовки, переносящиеся на 4+ строки, плотные таблицы,
   неоднозначное размещение nav CTA).

## Guardrails

- Никогда не изобретать новый контент, текст или изображения — всё берётся
  из десктоп-фрейма.
- Никогда не рестилизовать: цвета, шрифты, радиусы, тени остаются
  идентичны системе десктопа.
- Использовать существующие компоненты и их мобильные варианты из
  подключённой библиотеки, если они есть; отсоединять или пересобирать
  только когда ни один вариант не подходит, и отчитываться по каждому
  такому случаю.
- Если десктоп-фрейм использует breakpoint-специфичные компоненты
  (например `nav/desktop`), проверить библиотеку на наличие пары
  `nav/mobile`, прежде чем строить с нуля.
