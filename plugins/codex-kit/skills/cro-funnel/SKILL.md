# Диагностика воронки

## Общая методология (7 факторов)

Для любого этапа воронки — один и тот же набор факторов трения, до
специфики конкретного этапа:

| Фактор | Вопрос |
|---|---|
| Ясность | Понятно ли пользователю, что от него хотят и зачем, за 3 секунды? |
| Трение | Сколько шагов/полей/кликов между намерением и результатом — каждый лишний снижает конверсию |
| Доверие | Есть ли сигналы безопасности/легитимности в момент решения (для платных/личных данных особенно) |
| Мотивация | Понятна ли пользователю ценность именно сейчас, в этой точке — не абстрактно, а в контексте текущего действия |
| Отвлечение | Есть ли на экране элементы, конкурирующие за внимание с целевым действием |
| Обратная связь | Видит ли пользователь, что его действие сработало (подтверждение, прогресс) |
| Соответствие ожиданию | Совпадает ли то, что происходит после клика, с тем, что обещал предыдущий экран |

## Шаблон вывода: Issue / Impact / Fix / Priority

Единый формат для любого найденного трения — не смешивать
диагностику с решением до того, как оценена важность:

```markdown
## [Название точки трения]

**Issue**: [что именно происходит — конкретно, со скриншотом/шагом]
**Impact**: [на какую метрику влияет и оценочно насколько —
не «наверное много», а «вероятно теряем X% на этом шаге по паттерну
воронки»]
**Fix**: [конкретное предлагаемое изменение]
**Priority**: [High/Medium/Low — по формуле Impact × Ease, см.
`ab-testing/experiment-design` за ICE-приоритизацией, если находки
идут в бэклог экспериментов]
```

Каждая находка — гипотеза для теста, не готовое решение к немедленному
внедрению без проверки (если объём трафика позволяет A/B-тест — см.
блок `ab-testing`; если трафика мало для статзначимости — внедрять по
экспертной оценке, отслеживая качественную обратную связь).

## Частые ошибки

- Диагностика сразу предлагает Fix без чёткого Issue/Impact — решение
  без понимания причины часто чинит не ту проблему.
- Приоритизация по интуиции вместо Impact × Ease — мелкие, но заметные
  визуально проблемы обгоняют в очереди действительно дорогие точки
  потери.
- Один и тот же 7-факторный разбор применяется без специфики этапа
  (например доверие критично на paywall, но менее критично в
  середине онбординга) — общие факторы это стартовая точка, не полный
  список для каждого этапа.
