# Выбор и композиция чартов

Если задача - один чарт и понятно, какой, читать `dataviz` и не открывать
этот файл вообще. Этот блок нужен в трёх случаях: когда тип чарта неочевиден
и нужна быстрая таблица-подсказка, когда чартов несколько и они складываются
в отчёт/дашборд, и когда чарт уже готов и его нужно проверить на честность
данных перед показом.

## Граница с dataviz

`dataviz` уже даёт: как выбрать форму графика по задаче, цветовую формулу с
валидатором, спеки для подписей осей и легенд, правила взаимодействия
(hover, tooltip). Не пересказывать это здесь и не спорить с этим. Этот блок
добавляет три вещи, которых там нет: справочную таблицу для быстрого
попадания без чтения полного метода, композицию нескольких чартов в один
документ, и пост-фактум чек-лист для готового результата.

## Быстрая таблица: вопрос к данным → тип чарта

| Вопрос к данным | Тип чарта | Когда НЕ его |
|---|---|---|
| Сравнить категории между собой | Bar chart | Категорий больше 10-12 - свести к топ-N + "остальное" |
| Сравнить категории по нескольким сериям | Grouped bars | Серий больше 3-4 - переходить на small multiples |
| Сравнить факт с целью/планом | Bullet chart | Просто сравнение категорий без цели - обычный bar |
| Тренд непрерывной величины во времени | Line chart | Точек данных меньше 4-5 - просто числа текстом |
| Тренд с акцентом на объём/накопление | Area chart | Несколько несвязанных серий - путается с line |
| Тренд без контекста, инлайн в тексте/таблице | Sparkline | Читателю нужны точные значения - не sparkline, полный чарт |
| Доля от целого, 2-4 категории | Donut/pie | Категорий больше 5 - не читается, взять stacked bar |
| Доля от целого, много категорий, есть иерархия | Treemap | Иерархии нет - просто stacked bar без вложенности |
| Доля от целого, категорий много, без иерархии | Stacked bar | То же, что pie при малом числе категорий |
| Распределение одной величины | Histogram | Нужно сравнение медиан групп - box plot, не histogram |
| Сравнение распределений нескольких групп | Box plot | Группа одна - просто histogram |
| Связь двух величин | Scatter plot | Точек мало (<15) - таблица честнее графика |
| Связь трёх величин | Bubble chart | Третье измерение некритично - обычный scatter |
| Связь силы между двумя множествами | Heat map | Значений мало - таблица с подсветкой не нужна |
| Поток величины между стадиями | Sankey | Это структура процесса, не количество - тогда diagram-schemas, не чарт |

Таблица не заменяет форм-эвристику `dataviz`, только ускоряет первое
попадание. Если строка не подошла или данные не укладываются ни в одну -
идти в полный метод `dataviz`, не выдумывать промежуточный вариант на глаз.

## Композиция: несколько чартов в отчёт или дашборд

Идея режима "отчёт" происходит из lieflat-charts (идея, не код: там 12
полностраничных шаблонов под годовые отчёты/дашборды/брифы). Здесь - только
принцип раскладки, без готовых шаблонов чужого бренда:

1. **Один герой-чарт, не пять равных.** Если у отчёта есть главный вопрос,
   у него один главный чарт, остальные - подтверждающий контекст меньшего
   размера. Пять чартов одинакового веса не расставляют приоритет за
   читателя, значит расставляет он сам, медленно.
2. **Stat-tile строка перед графиками.** Три-пять ключевых чисел с подписью
   и трендом (стрелка/спарклайн) в одну строку сверху - читатель получает
   выводы до того, как разбирается в графиках.
3. **Единая сетка, не разнобой размеров.** Все чарты отчёта садятся на одну
   grid-сетку (та же логика, что 4px-сетка в `diagram-schemas`, но для
   макета страницы, а не диаграммы) - иначе визуальный шум от несогласованных
   отступов забивает сами данные.
4. **Один источник цвета на весь отчёт.** Категория "выручка" красная на
   одном чарте и синяя на другом внутри одного отчёта - это ошибка
   согласованности, а не вариативность. См. `references/tokens.md`.
5. **Не больше одного chart-типа на паттерн сравнения.** Если три чарта на
   одной странице отвечают на один и тот же тип вопроса ("сравнение
   категорий"), они должны быть одним и тем же типом чарта, не bar на одном
   и donut на другом ради разнообразия.

## Файл токенов чарта - источник правды

Идея из lieflat-charts (`mono-tokens.js`, идея использована, код нет):
цвета, радиусы карточек, тайминги анимации, минимальный кегль подписи
хранятся в одном файле/константе, не разбросаны по инлайн-стилям каждого
чарта. Если проект уже прогнал `web-color`, брать оттуда рампу и не заводить
вторую. Подробности ролей токенов - [references/tokens.md](references/tokens.md).

## Чек-лист честности данных перед выдачей

Каждый пункт да/нет, не оценка на глаз:

- [ ] Ось Y столбчатого/полосового чарта начинается с нуля (обрезанная ось
      искажает визуальное сравнение величин - это не стилистика, это ложь).
- [ ] Если ось всё же обрезана намеренно (научные данные с малым разбросом),
      разрыв оси подписан явным значком, не спрятан.
- [ ] Цветовое кодирование одной категории одинаково на всех чартах одного
      документа.
- [ ] Есть хотя бы одна альтернатива цвету для различения категорий
      (паттерн, форма маркера, прямая подпись) - не полагаться только на
      цвет.
- [ ] Числа на чарте и числа в исходных данных совпадают при перепроверке
      (не округлены так, что сумма долей не даёт 100%).
- [ ] Подпись оси и единица измерения присутствуют, не подразумеваются.
- [ ] На малом экране чарт либо упрощается (меньше точек, крупнее подписи),
      либо заменяется таблицей - не сжимается до нечитаемого.
