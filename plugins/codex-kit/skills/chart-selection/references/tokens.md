# Файл токенов чарта

> Паттерн "один файл токенов = единственный источник правды" взят из идеи
> lieflat-charts (`mono-tokens.js`), реализация здесь своя, кода источника
> не использовано (лицензия PolyForm Noncommercial это запрещает).

Один набор именованных ролей на весь документ с чартами, не отдельные
hex/px в разметке каждого чарта. Смена одного значения в этом файле красит
весь отчёт разом, а не заставляет искать каждое вхождение по тексту.

## Роли (не конкретные значения)

| Роль | Назначение | Источник значения |
|---|---|---|
| `axis` | Линии осей, деления | нейтральный приглушённый из рампы `web-color` |
| `gridline` | Фоновые направляющие линии | тот же нейтральный, но слабее (низкая непрозрачность) |
| `label` | Подписи осей, значений | основной текстовый токен проекта |
| `series-1..N` | Цвет каждой серии данных | категориальная рампа `web-color`, не выдуманные на глаз оттенки |
| `highlight` | Выделенная серия/точка | акцентный токен, тот же, что `focal` в `diagram-schemas` |
| `threshold` | Линия цели/нормы/плана | отдельный токен, визуально отличимый от `series-*` (обычно пунктир) |
| `negative` | Отрицательные значения, если знак важен | не обязательно красный по умолчанию - красный/зелёный только если продукт уже использует их для статуса |

## Числовые константы, которые стоит зафиксировать один раз

- Минимальный размер подписи на чарте (не мельче, чем нижний предел
  основной типографики проекта - если в интерфейсе минимум 12px, на чарте
  не должно быть 9px).
- Радиус углов у карточек-контейнеров чарта, если чарты садятся в карточки
  (согласовать с `radius-md`/`radius-lg` из `diagram-schemas`, чтобы отчёт
  с диаграммами и чартами не выглядел как два разных продукта).
- Длительность анимации входа данных (если есть) - одно значение на все
  чарты документа, не у каждого своё.

## Когда не заводить отдельный файл токенов

Один чарт, разовая задача, без отчёта из нескольких графиков - не нужно,
это оверинжиниринг ради одного использования. Файл токенов оправдан начиная
с трёх и более чартов в одном документе.
