# icons0.dev

Ставится как есть, апстрим (`marcoripa96/i0`) не копируется. MIT.

## Путь 1 — известна иконка: shadcn-реестр, без ключа

Ключ не нужен, вызов явный, ничего не висит фоном. Использовать по
умолчанию, когда имя иконки и коллекция уже известны (например, из
результата поиска в вебе на icons0.dev или из прошлого вызова MCP):

```bash
npx shadcn@latest add https://icons0.dev/r/lucide:home.json
npx shadcn@latest add https://icons0.dev/r/lucide:home.json https://icons0.dev/r/tabler:arrow-right.json
npx shadcn@latest add https://icons0.dev/r/lucide.json   # вся коллекция
```

Кладёт типизированный React-компонент прямо в проект (обычно
`components/icons/`), без рантайм-зависимости на icon-пакет — SVG уже
внутри компонента.

```tsx
import { LucideHome } from "@/components/icons/lucide-home";
```

## Путь 2 — иконка неизвестна: MCP, с ключом

Использовать только когда нужен поиск по смыслу или обзор коллекций —
задача, которую одной командой не закрыть. **Ключ уже получен пользователем
и звучал в переписке — если он ещё не перевыпущен, сделать это в первую
очередь**, старый значился публично в чате, значит скомпрометирован.

Сервер уже описан в `.mcp.json` этого блока через `${ICONS0_API_KEY}` —
руками `claude mcp add` выполнять не нужно, достаточно один раз задать
переменную окружения перед стартом Codex:

```bash
export ICONS0_API_KEY=i0_...   # или в .env / переменные окружения системы
```

Codex сам подставит значение при подключении MCP-сервера. Сырой
ключ никогда не попадает в файлы каталога — только имя переменной
(`requires_env: [ICONS0_API_KEY]` в `block.yaml`, `${ICONS0_API_KEY}` в
`.mcp.json`).

Четыре инструмента:

- **`search-icons`** — поиск по ключевому слову или обзор коллекции:
  `{ "query": "arrow left" }`, `{ "query": "home", "collection": "lucide" }`,
  `{ "collection": "tabler", "category": "Navigation" }`.
- **`get-icon`** — получить SVG или React-компонент, пачкой до 20 штук:
  `{ "name": "lucide:home", "format": "react" }`,
  `{ "name": ["mdi:home", "lucide:home", "tabler:home"] }`.
- **`list-collections`** — какие коллекции есть, с фильтром по категории/
  имени.
- **`list-licenses`** — лицензии всех коллекций со счётчиком иконок.

После того как нужное имя найдено через `search-icons`/`list-collections` —
дальнейшую установку делать Путём 1 (shadcn-реестр), не через `get-icon`:
результат тот же, но без постоянно висящего MCP-вызова на каждую иконку.

## Соседние блоки

`shadcn-official` — тот же CLI, тот же механизм установки компонента. Иконка
через icons0 ничем не отличается от обычного shadcn-компонента после
установки — это просто ещё один React-компонент в `components/`.

## Проверяемый результат (для /loop-build)

Готово — когда файл компонента иконки появился по ожидаемому пути
(`components/icons/<name>.tsx` или как настроено в `components.json`) и
импортируется без ошибки. Реальная команда: путь существует + `tsc`/сборка
не падает на нём.

## Несколько иконок сразу — распараллелить

Устанавливаешь пачку иконок за один заход — `npx shadcn add` уже
принимает список компонентов в одном вызове, agent-параллелизация здесь
избыточна, инструмент это уже умеет одной командой. Агентов заводить
только если для каждой иконки нужен ещё и разбор, куда её вставить в код
(тогда subagent на место использования, не на установку).
