Прогони цикл по скиллу `discovery-cycle` в блоке `product-discovery`.

Один проход без субагентов, модель/эффорт не спрашивать — задача
одношаговая по своей природе, сложность не в объёме, а в порядке.

Сначала спроси (если не ясно из `$ARGUMENTS` или контекста), продукт
уже существует или это идея с нуля — от этого зависит, какой вариант
шаблона брать на каждом шаге.

Обязательно по порядку, не пропускать и не менять местами:

1. **Идея** — `templates/brainstorm-ideas-existing.md` или
   `-new.md`. Multi-perspective (PM/дизайнер/инженер), не один ответ.
2. **Допущения** — `templates/identify-assumptions-existing.md` или
   `-new.md`. Явный список рискованных допущений по идее из шага 1.
3. **Приоритизация допущений** — `backlog-triage/templates/
   prioritize-assumptions.md`. Что тестировать первым по матрице
   Impact × Risk.
4. **Эксперимент** — `templates/brainstorm-experiments-existing.md`
   или `-new.md`, только на допущение(я) с верхних строк шага 3, не
   на всё сразу.

Не давать эксперимент без явного списка допущений из шага 2 — если
пользователь просит сразу эксперимент, вернуться на шаг 2 сначала,
объяснить зачем.

Вывод — один markdown-документ с четырьмя секциями по шагам, не
россыпь отдельных файлов.
