# Вариации без повторов

50 архетипов компонентов, организованных по категориям: Heroes (H1-H9),
Section heads (S1-S5), Feature blocks (F1-F6), CTA (C1-C4), Testimonials
(T1-T4), Footers (Ft1-Ft8), Navigation (N1-N13, включая N1a/N1b). На
каждый архетип — короткая структурная подсказка.

Полный словарь (все 50, с within-archetype variation knobs и таблицами
жанр→архетип) — [component-cookbook.md](component-cookbook.md), дословно
на английском.

## Правило diversification

Внутри одной страницы два раздела не используют один архетип. Следующая
страница берёт другие архетипы из тех же категорий, не повторяет прошлый
выбор.

## Within-archetype variation knobs

Не просто "выбрать архетип", а настроить 2-3 параметра внутри него.
Пример из источника (H2 Split Diptych): Ratio `7/5`/`6/6`/`5/7`, Right
side `photo`/`proof column`/`pull-quote`, Divider `hairline`/
`negative-space`/`vertical-rule`.

Выбранные значения фиксируются в CSS-комментарии-stamp:

```
/* Hallmark · macrostructure: Bento Grid · F1 Bento knobs: tiles=6, spans=irregular, accent=corner-only · ... */
```

Тот же stamp, который потом сверяет `design-system-docs/audit` — «дрейф»
это когда сборка утверждает один набор knobs в комментарии, а по факту
отрисовано другое.

## Предупреждение про шаблонные паттерны

Источник прямо называет самый узнаваемый признак шаблонной вёрстки: рефлекторный
"wordmark + inline links + button-right" (архетип N1a) — таблицы жанр→
архетип в источнике явно советуют уводить от него по умолчанию.

## Mobile collapse

Для каждого архетипа расписано поведение на брейкпоинтах `60rem` и
`40rem` — не отдельная забота, часть самого архетипа.

## Соседние блоки

`design-system-docs` — тот же механизм CSS-stamp, но на другой стороне:
там `audit` сверяет stamp с реальной страницей (контроль), здесь —
выбор архетипа и knobs (генерация). `taste-skill` (отдельный блок) —
`DESIGN_VARIANCE`-слайдер задаёт координаты вариации заранее, до выбора
конкретного архетипа. `figma-canvas/flow-explore`
(`screen-alternatives`) — та же задача генерации альтернатив, но
исполнение на холсте Figma, не в коде.

## Проверяемый результат (для /loop-build)

Правило diversification механически проверяемо: ни один архетип не
повторяется в соседних разделах. Готово — когда список
раздел→архетип, прочитанный подряд, не содержит двух одинаковых
архетипов рядом (скрипт-сверка списка, не суждение).

## Несколько разделов сразу — распараллелить

Собираешь вариации сразу для многих разделов страницы — subagent на
раздел **опасен без координации**: два параллельных агента могут
независимо выбрать один и тот же архетип для соседних разделов и
нарушить diversification, которую видно только при сравнении всех
разделов разом. Либо: один агент резервирует архетипы по всем разделам
сначала (быстро, дёшево), потом subagent на раздел уже пишет вариацию
под зарезервированный архетип — тогда параллельно безопасно.
