# Дизайн процесса команды

5 инструментов из `Owl-Listener/ux-pgm-skills`, обобщены от UX-команды
до любой команды. Общий принцип всех пяти — минимально достаточно,
каждый шаг должен окупать свою цену трением. Файлы в `templates/`
дословно на английском, атрибуция в начале каждого.

## Какой инструмент когда

| Запрос пользователя | Файл | Что делает |
|---|---|---|
| «спроектируй управление программой» | `templates/governance-model.md` | Decision rights, минимальный набор форумов, каданс, пороги эскалации — тест лёгкости на каждый шаг |
| «почему процесс буксует» | `templates/process-retrospective.md` | Процесс как он реально идёт (не как задокументирован) → узкие места по данным (cycle time, rework, drop-off) → 1-2 точечных изменения |
| «нужны ли нам все эти митинги» | `templates/ritual-design.md` | Для каждого ритуала — одна цель, каданс под скорость изменения темы, критерий отмены |
| «сделай playbook из этого подхода» | `templates/scaling-playbook.md` | Что реально сработало (включая неаккуратные детали) → условия применения, роли, шаги с шаблонами, что можно менять, что нельзя |
| «нарисуй workflow команды» | `templates/workflow-design.md` | Стадии, критерии входа/выхода, хендоффы, гейты, петли обратной связи — оптимизация на поток, не на эффективность одной стадии |

## Как выбирать

`process-retrospective` и `ritual-design` — диагностика уже
существующего (что чинить), `governance-model` и `workflow-design` —
проектирование структуры (что должно быть). `scaling-playbook` — после
того, как подход уже проверен и работает, не раньше.

**`process-retrospective` — третий altitude ретро** в каталоге, после
`product-execution/sprint-cycle/retro` (один спринт, 2-3 action item) и
`program-delivery/delivery-execution/retrospective` (одна программа
целиком). Этот — про процесс команды в целом, не привязан к спринту
или программе, годами тот же процесс. Не путать три уровня без явного
уточнения масштаба у пользователя.

Не убирать трение из процесса, не спросив зачем оно там — источник
прямо предупреждает: часть трения защищает качество, chestnut не
резать вслепую.
