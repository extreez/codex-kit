# Форматы бэклог-айтемов

4 шаблона из `pm-skills` (phuryn) — разные форматы записи одной и той же
задачи «превратить требование в готовый к разработке айтем». Файлы в
`templates/` дословно на английском, атрибуция в начале каждого.

## Какой формат когда

| Запрос пользователя | Файл | Формат |
|---|---|---|
| «напиши user story» | `templates/user-stories.md` | «As a [роль], I want to...» + 3 C's (Card/Conversation/Confirmation) + INVEST, 4-6 acceptance criteria |
| «сделай job story» | `templates/job-stories.md` | «When [ситуация], I want to [мотивация], so I can [исход]» — фокус на контексте, не на роли |
| «оформи в формате WWA» | `templates/wwas.md` | Why (связь с целью) / What (1-2 абзаца) / Acceptance — минимум предписаний, максимум автономии команды |
| «напиши тест-кейсы к этой истории» | `templates/test-scenarios.md` | Готовая история → сценарии: starting conditions, роль, шаги, ожидаемый результат, edge cases |

## Как выбирать

User story, job story и WWA — три альтернативы одной задачи, не три
шага подряд. Выбор зависит от того, что уже принято в команде:

- **User story** — стандарт по умолчанию, если команда не указала
  другой формат. Требует роль пользователя.
- **Job story** — когда роль неважна или размыта, важна ситуация
  («when I'm commuting», не «as a commuter»).
- **WWA** — когда команде нужна стратегическая рамка (Why), но не
  нужна жёсткая спецификация (What останется кратким, доработка
  на усмотрение команды).

Не переписывать один и тот же айтем во всех трёх форматах без запроса
— один запрос, один формат, если явно не попросили сравнить.

`test-scenarios` идёт после любого из трёх форматов — берёт готовую
историю и её acceptance criteria как вход, не создаёт новую историю.
Без готовой истории/критериев сначала спросить их, не выдумывать.
