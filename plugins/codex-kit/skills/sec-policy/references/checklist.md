# Мастер-чеклист безопасности

Единственный источник правил для всех блоков `sec-*`. Язык-агностик: пункт
описывает угрозу и признак, а не синтаксис фреймворка. Проверку под конкретный
стек генерирует `sec-audit` после детекта.

Каждый пункт: **ID**, угроза человеческим языком, **признак дыры** (что искать),
**критерий закрытия** (когда считается закрытым).

Пункты не противоречат друг другу и не дублируют слои. Хук `guard-write`
блокирует запись, аудит ищет уже написанное, тесты закрывают критерий.

---

## A. Доступ и авторизация

**AC-1. Объект чужой, а отдаётся.** (OWASP A01, вайб №4)
Признак: эндпоинт берёт `id` из запроса и отдаёт/меняет запись, проверив только
что пользователь залогинен, но не что запись его.
Критерий: каждый доступ по id сверяет владельца с текущим пользователем на сервере.

**AC-2. Роль проверяет только фронт.** (OWASP A01, вайб №5)
Признак: админ-действие спрятано кнопкой в UI, но эндпоинт роль не проверяет.
Критерий: каждое привилегированное действие проверяет роль на сервере.

**AC-3. Проверка прав на клиенте.** (30 правил №23)
Признак: решение «можно ли» принимается в браузере.
Критерий: авторизация только на сервере; UI-проверка допустима лишь как удобство.

**AC-4. База открыта на чтение из фронта.** (вайб №13)
Признак: Supabase/Firebase/любая BaaS подключена из браузера без правил доступа
на стороне базы. RLS выключен хотя бы на одной таблице.
Критерий: RLS (или аналог) включён на всех таблицах, у каждой явная политика.

## B. Аутентификация и сессии

**AU-1. Форму входа перебирают.** (вайб №1, 30 правил №15-16)
Признак: вход принимает попытки без лимита.
Критерий: лимит на IP и на логин (старт: 5 попыток / 15 мин), для сброса пароля
жёстче (3 / час), дальше временная блокировка.

**AU-2. Ответ выдаёт наличие email.** (вайб №2)
Признак: при неверном входе видно, есть такой email или нет.
Критерий: ответ одинаков для «нет пользователя» и «неверный пароль».

**AU-3. Слабый пароль и нет 2FA у админов.** (вайб №2, 30 правил №2)
Признак: пароль короче 12 символов проходит; у админа нет второго фактора.
Критерий: минимум 12 символов, 2FA для админов, свой auth не собран руками
(готовый провайдер).

**AU-4. Долгая сессия без ротации.** (30 правил №1)
Признак: токен живёт неограниченно, refresh не ротируется.
Критерий: срок жизни ограничен (ориентир: JWT ≤ 7 дней), refresh ротируется.

**AU-5. Фиксация сессии.** (OWASP A07)
Признак: идентификатор сессии не меняется после входа — атакующий подсовывает
жертве свой, потом входит под ней.
Критерий: сессия пересоздаётся при логине и смене привилегий.

## C. Секреты

**SE-1. Ключ уехал в браузер.** (вайб №3, 30 правил №3)
Признак: секрет попал в код фронтенда — виден через просмотр исходника.
Критерий: секреты только на сервере, в браузер не уходят.

**SE-2. Секрет в git-истории.** (вайб №3, 30 правил №4)
Признак: `.env` или ключ в коммитах; `.gitignore` добавлен поздно.
Критерий: секретов в истории нет, `.env` в `.gitignore`, засветившийся ключ
перевыпущен (спрятать мало).

**SE-3. Секреты не ротируются.** (30 правил №5)
Признак: ключи живут годами.
Критерий: ротация не реже 90 дней.

## D. Ввод и вывод

**IN-1. Ввод склеивается в SQL.** (OWASP A03, вайб №6)
Признак: данные пользователя попадают в SQL склейкой строк.
Критерий: только параметризованные запросы или ORM.

**IN-2. Ввод пользователя как HTML.** (OWASP A03, вайб №9)
Признак: текст пользователя выводится на страницу без экранирования
(`innerHTML`, `dangerouslySetInnerHTML`, шаблон без автоэкранирования).
Критерий: вывод экранируется; сырой HTML только из доверенного источника.

**IN-3. Ввод в команду ОС / путь файла.** (OWASP A03)
Признак: ввод попадает в шелл-команду или путь без валидации.
Критерий: без конкатенации в команду; пути ограничены и нормализованы.

**IN-4. eval / динамическое выполнение ввода.** (OWASP A03)
Признак: ввод (или вывод модели) попадает в `eval`, `Function`, `exec`,
десериализацию, шаблонизатор с выполнением.
Критерий: недоверенные данные не исполняются; вывод LLM тоже недоверенный (см. AI-*).

**IN-5. NoSQL / инъекция в не-SQL хранилище.** (OWASP A03)
Признак: ввод склеивается в запрос Mongo/Redis/поисковый индекс, объект-оператор
доходит до запроса (`{$gt:""}`).
Критерий: типизация и валидация ввода, операторы из ввода не проходят.

## E. Загрузка файлов

**UP-1. Тип файла по расширению.** (вайб №11, 30 правил №20)
Признак: тип проверяется по имени `.png`, не по содержимому.
Критерий: тип по сигнатуре содержимого; файл переименовывается; хранится вне
папки, откуда сервер исполняет код; размер ограничен.

## F. Лимиты и деньги

**RL-1. Нет rate-limit на эндпоинтах.** (30 правил №14-15)
Признак: эндпоинт (включая mobile API) принимает запросы без потолка.
Критерий: rate-limit с первого дня (старт: 100 req/час/IP).

**RL-2. Платный API без лимита на пользователя.** (вайб №14, 30 правил №17)
Признак: сервис ходит в платную модель/SMS/картинки без лимита на пользователя
и без общего потолка расходов.
Критерий: суточный лимит на пользователя + общий потолок, после которого отказ;
расход считается по каждому пользователю.

**RL-3. Гонка на критичной операции.** (вайб №12)
Признак: списание баланса, промокод, вывод средств не атомарны — сто
одновременных запросов проходят все.
Критерий: транзакция с блокировкой строки или идемпотентный ключ операции.

**RL-4. Исчерпание ресурсов / DoS.** (OWASP, Cloudflare)
Признак: запрос без лимита раздувает память/CPU — огромный upload, глубокий
JSON, неограниченный список, тяжёлый регэксп на вводе.
Критерий: лимиты размера тела, глубины, пагинации; таймауты; защита от
катастрофического бэктрекинга регэкспа.

**BL-1. Обход бизнес-логики.** (OWASP A04, Cloudflare)
Признак: шаги процесса можно пройти не по порядку или пропустить — оплата после
выдачи, смена статуса в обход проверки, отрицательное количество.
Критерий: сервер проверяет допустимость перехода состояния, не только формат.

## G. Внешние границы

**EX-1. Вебхук платёжки без проверки.** (вайб №7, 30 правил №21)
Признак: обработчик вебхука открывает доступ по знакомому формату без проверки
подписи, суммы, валюты, без защиты от повтора.
Критерий: сверяется подпись, сумма и валюта, есть защита от повторной доставки.

**EX-2. CORS со звёздочкой.** (вайб №10, 30 правил №12)
Признак: `Access-Control-Allow-Origin: *`, тем более вместе с куками.
Критерий: список конкретных доменов; wildcard и куки одновременно запрещены.

**EX-3. Открытый redirect.** (30 правил №13)
Признак: redirect на URL из запроса без allow-list.
Критерий: redirect только на адреса из белого списка.

**EX-4. SSRF — сервер ходит по ссылке из запроса.** (OWASP A10)
Признак: сервер делает запрос на URL/хост из ввода (загрузка по ссылке, вебхук,
превью) без проверки. Можно увести на внутренний адрес (`169.254.169.254`,
`localhost`, приватная сеть).
Критерий: allow-list схемы и хоста, отказ приватным IP, защита от DNS-rebinding,
без следования редиректам на серверных запросах.

**EX-5. CSRF — чужой сайт шлёт запрос от имени пользователя.** (OWASP A01)
Признак: меняющий состояние запрос принимается по одной куке-сессии, без
CSRF-токена или проверки Origin/SameSite.
Критерий: CSRF-токен на форму, или SameSite-куки, или проверка Origin на
меняющих запросах.

## H. Зависимости и цепочка поставки

**DE-1. Пакет не проверен.** (вайб №8, 30 правил №6-8)
Признак: библиотека поставлена не глядя (автор, живость, дата обновления);
`npm audit`/аналог не гоняется.
Критерий: пакет существует и жив, аудит уязвимостей в CI, обновление
устаревшего, запрос свежих безопасных версий.

**DE-2. Промпт-инъекция через чужой скилл/пакет.** (вайб №15)
Признак: скилл/пакет с GitHub ставится без проверки содержимого.
Критерий: содержимое проверено (см. скилл `skill-wall`), источник известен.

**DE-3. Install-скрипты и плавающие версии.** (supply chain)
Признак: postinstall-скрипты пакетов выполняются по умолчанию; нет lock-файла;
CI ставит не из lock.
Критерий: install-скрипты по умолчанию заблокированы; один lock-файл; CI ставит
из lock (frozen/immutable).

## I. Эксплуатация

**OP-1. Нет логов критичных действий.** (30 правил №26)
Признак: удаления, смена ролей, платежи, экспорты не логируются.
Критерий: критичные действия логируются с кем/что/когда.

**OP-2. console.log с данными в проде.** (30 правил №11)
Признак: отладочный вывод с данными остаётся в релизе.
Критерий: перед релизом отладочный вывод убран.

**OP-3. test и prod не разделены.** (30 правил №29-30)
Признак: тестовый вебхук/ключ трогает реальные системы; одна база на оба контура.
Критерий: контуры разделены полностью; тестовое не касается реального.

**OP-4. Нет проверяемых бэкапов.** (30 правил №28)
Признак: бэкап есть, восстановление ни разу не проверяли.
Критерий: бэкап автоматический, восстановление проверяется.

**OP-5. Нет флоу удаления аккаунта.** (30 правил №27)
Признак: пользователь не может удалить свои данные (риск по GDPR).
Критерий: рабочий флоу удаления аккаунта и данных (включая бэкапы, кэш, индексы).

**OP-6. Ошибка выдаёт внутренности.** (OWASP A05)
Признак: stack trace, путь файла, версия, SQL-текст уходят в ответ пользователю.
Критерий: наружу общая ошибка, детали только в лог.

## J. Транспорт и заголовки

**TR-1. Нет HTTPS / слабый TLS.** (security-baseline)
Признак: доступ по HTTP; TLS 1.0/1.1 включён; нет HSTS.
Критерий: только HTTPS, TLS ≥ 1.2, HSTS с includeSubDomains.

**HD-1. Нет заголовков безопасности.** (security-baseline)
Признак: нет CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy.
Критерий: CSP (лучше nonce/hash), `nosniff`, защита от кликджекинга, Referrer-Policy.

**DP-1. Чувствительные данные наружу / не шифрованы.** (OWASP A02)
Признак: PII в ответе API без нужды; секреты/PII в покое без шифрования; поля не
классифицированы.
Критерий: лишние поля не отдаются; PII шифруется в покое; хранение и срок
осознаны.

## K. LLM / AI-фичи

Для проектов с обращением к модели. Вывод модели — недоверенный ввод.

**AI-1. Вывод модели исполняется.** (OWASP LLM)
Признак: ответ LLM попадает в `eval`, SQL, шелл, `innerHTML`, вызов инструмента
без проверки.
Критерий: вывод модели санитайзится как любой недоверенный ввод (см. IN-1..IN-4).

**AI-2. Секреты и чужие данные в промпте.** (OWASP LLM)
Признак: в контекст модели уходят ключи, или данные одного пользователя видит
другой.
Критерий: секреты вне промпта; в промпт только данные текущего пользователя.

**AI-3. Инструменты агента без рамок.** (OWASP LLM)
Признак: агент/LLM-инструмент может удалять, платить, менять без подтверждения и
без ограничения прав.
Критерий: права инструмента минимальны; разрушительное действие требует
подтверждения; лимит на токены/запросы/циклы (см. RL-2).

**AI-4. RAG без изоляции по тенантам.** (OWASP LLM)
Признак: векторное хранилище общее, поиск достаёт чужие документы.
Критерий: разделение хранилища/фильтр по тенанту, чужое не выдаётся.
