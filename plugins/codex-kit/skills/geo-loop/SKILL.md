# geo-loop

Автоматизирует `geo-optimize` двумя механизмами: гейт на выходе из сессии,
цикл до порога. По образцу `sec-loop`, числовой гейт вместо счётчика
находок (ближе к идее «поднимать score» — cм. параллель с CWV-порогами
в `web-fundamentals`, только composite вместо LCP/CLS/INP).

## 1. Stop-гейт (хук, уже активен блоком)

Хук `stop-gate.js` не даёт закончить сессию, если менялись страницы/
шаблоны/`llms.txt`/`llms-full.txt`/`robots.txt`, а `/geo-optimize` не
прогнан. Напоминает один раз.

## 2. Цикл оценка-фикс-переоценка до порога

Критерий проверяемый: **composite score ≥ 70/100** в последнем отчёте
`geo-optimize`.

### Почему 70, а не 100

Composite складывается из категорий с разной природой (см.
`geo-optimize/references/composite-score.md`). Часть весов (brand
authority, platform-specific — суммарно 30%) зависит от факторов вне
прямого контроля одной правки контента/техники — узнаваемость бренда и
присутствие на конкретной AI-платформе растут медленнее и не гоняются
циклом за один прогон. Требовать 100 значит держать цикл открытым
бесконечно на факторах, которые цикл не может починить за один проход.
70 — порог, при котором citability/E-E-A-T/technical/schema (70% веса,
то, что реально чинится правками) в хорошем состоянии, а на оставшийся
разрыв нужна отдельная стратегия (`geo-content` для платформенной
адаптации, `seo-offpage`-подобная работа для brand authority — вне
разового цикла).

Порог можно пересогласовать с пользователем под конкретный проект —
70 это разумный дефолт, не догма.

### Один проход

1. `/geo-optimize` по изменённому (или по всему проекту).
2. Приоритет фикса по весу: сначала citability (25%) и E-E-A-T (20%) —
   находки от `citability-scorer`; затем brand/platform, затем
   technical/schema.
3. Фикс не переписывает контент без подтверждения.
4. Снова `/geo-optimize`. Composite ≥ 70 — стоп. Иначе новый проход.

Собирается через `/goal` и/или `/loop` (скилл `loop-build`). Модель,
эффорт и количество субагентов под каждый шаг спрашиваются при запуске
(правило).

## Границы

- Не гарантирует появление в конкретном AI-ответе — composite score
  измеряет управляемые сигналы, не итоговое поведение чужой модели.
- Не путать с `seo-loop` (цикл для technical SEO находок, другая метрика).
