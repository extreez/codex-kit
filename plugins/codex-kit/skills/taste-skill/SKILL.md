# taste-skill

Ставится как есть через `npx skills add`, апстрим не копируется в этот
блок. Правки — только через апстрим-репозиторий.

## Установка

```bash
npx skills add Leonxlnx/taste-skill
```

## Три dial'а

| Dial | 1 | 10 |
|---|---|---|
| `DESIGN_VARIANCE` | строгая симметрия (12-col grid, равные fr-юниты) | artsy-хаос (masonry, `padding-left: 20vw`) |
| `MOTION_INTENSITY` | без автоматических анимаций | сложные scroll-triggered reveals |
| `VISUAL_DENSITY` | art gallery / воздух | cockpit / плотные данные |

Значения выводятся из сигналов брифа (таблица «сигнал → dial'ы» в
апстриме, например «trust-first/regulated» даёт низкие значения по всем
трём). Жёсткие правила на стыке уровней зашиты в сам скилл: выше
`MOTION_INTENSITY 3` обязателен `prefers-reduced-motion`, выше
`DESIGN_VARIANCE 4` асимметрия обязана схлопываться в одну колонку на
мобильном.

## Форк-варианты

Устанавливаются отдельно, не автоматически вместе с базовым скиллом:
`brutalist-skill` (Swiss Print / CRT Terminal архетипы), `minimalist-skill`
(банит Inter/Roboto, банит `shadow-md/lg/xl`), `gpt-tasteskill`
(псевдослучайная архитектура через сид от длины промпта, под GPT/Codex).
Список полный — в самом репозитории, не дублируется здесь.

## Соседние блоки

`impeccable` калибрует и правит постфактум (детектор + команды), taste-skill
параметризует заранее (бриф → числа → паттерны) — разные стадии, ставить
можно оба. `web-taste/gate-check` может использоваться после того, как
дизайн собран по этим координатам, как независимая финальная проверка.

## Проверяемый результат (для /loop-build)

Механическое — 3 dial'а детерминированно определяют CSS-паттерны,
значит есть настоящая команда: пересчитать ожидаемые значения из
DESIGN_VARIANCE/MOTION_INTENSITY/VISUAL_DENSITY по формуле скилла и
сравнить diff'ом с тем, что реально в CSS. Готово — когда diff пустой.

## Несколько компонентов сразу — распараллелить

Один и тот же набор из 3 dial'ов применяется сразу к многим компонентам —
subagent на компонент, гонки нет: все читают одну и ту же конфигурацию
dial'ов, не пишут в неё. Меняются сами значения dial'ов (не компоненты) —
это одно решение на весь проект, не параллелить, слишком мелко и рискует
разными агентами выбрать разные числа.
