# Группировка и выравнивание

Как отступ, форма, общие края и порядок сообщают, что принадлежит друг
другу и что важнее.

## Группируй пространством, не линиями

Три инструмента группировки, по приоритету:

1. **Негативное пространство**, дефолт. Связанные элементы близко,
   несвязанные — далеко.
2. **Фоновые формы**, карточка или заполненный контейнер, где группа
   должна читаться как единица — выбираемая строка, перетаскиваемая
   карточка.
3. **Разделительные линии**, последний ресурс для плотных данных, где
   пространство стоит слишком дорого — таблицы, длинные списки настроек.

Структурное правило: отступ между группами минимум в 2 раза больше отступа
внутри группы. При `8px` внутри группы, между группами нужно `16px`+,
иначе взгляд не может понять, где кончается одна группа.

```css
/* Хорошо: только отступ сообщает группировку */
.field-group { display: flex; flex-direction: column; gap: 8px; }
.form { display: flex; flex-direction: column; gap: 24px; }

/* Плохо: равномерный отступ плюс линии для компенсации */
.form > * { margin-bottom: 12px; border-bottom: 1px solid var(--separator); }
```

```html
<!-- Хорошо: Tailwind -->
<div class="space-y-6">
  <div class="space-y-2">…группа полей…</div>
  <div class="space-y-2">…группа полей…</div>
</div>
```

Где разделитель реально нужен — держи его тихим: hairline-толщина, низкий
контраст, никогда не сочетать с большим отступом, который уже сделал эту
работу.

## Держи контролы отличимыми от контента

Интерактивным элементам нужен визуальный сигнал: фон, граница, подчёркивание
или размещение в постоянной зоне контролов — тулбар, строка футера. Контрол,
стилизованный идентично статичному тексту, невидим.

```html
<!-- Плохо: действие выглядит точно как текст описания рядом с ним -->
<p class="text-zinc-600">Ваш пробный период скоро закончится. Обновите план</p>

<!-- Хорошо: действие читается как действие -->
<p class="text-zinc-600">Ваш пробный период скоро закончится.</p>
<button class="font-medium text-blue-600">Обновить план</button>
```

Обратное тоже верно. Некликабельный бейдж, оформленный точно как соседние
кнопки, собирает мёртвые клики.

## Выравнивай по общим краям

Выбери небольшой набор краёв выравнивания и посади на них всё — взгляд
отслеживает прямые края, чтобы сканировать контент.

- Каждый случайный край читается как шум, даже когда никто не может его
  назвать: иконка на 2px не по краю текста, карточка с непохожими на
  соседей паддингами.
- Используй один шаг отступа проекта для выражения иерархии. `16px` —
  полезный дефолт при отсутствии шкалы, более глубокая вложенность
  повторяет тот же шаг.
- Числа в таблицах выравниваются по последующему краю, текст — по
  ведущему. Табличные цифры — забота `typography`.

```css
/* Хорошо: один общий ведущий край, один шаг отступа */
.section { padding-inline: 24px; }
.section .child { margin-inline-start: 16px; }

/* Плохо: три несвязанных ведущих края в одной колонке */
.header { padding-inline-start: 20px; }
.list-item { padding-inline-start: 14px; }
.footer { padding-inline-start: 24px; }
```

## Логические свойства, не физические

Выражай направленно-зависимую горизонтальную позицию как leading/trailing,
чтобы layout автоматически зеркалился под `dir="rtl"`:

| Физическое (избегать) | Логическое (использовать) |
| --- | --- |
| `margin-left` | `margin-inline-start` |
| `padding-right` | `padding-inline-end` |
| `left: 0` | `inset-inline-start: 0` |
| `text-align: left` | `text-align: start` |
| `border-right` | `border-inline-end` |

```html
<!-- Хорошо: логические утилиты Tailwind -->
<div class="ms-4 pe-6 text-start">…</div>

<!-- Плохо: ломается в RTL -->
<div class="ml-4 pr-6 text-left">…</div>
```

Физические свойства оставлять только для того, что относится к физической
стороне экрана независимо от языка — позиционирование против выреза
устройства, соответствие направлению жеста.

Там, где расположение кодирует прогрессию — звёздный рейтинг, индикатор
шага, progress bar — последовательность зеркалится в RTL, звёзды
заполняются с последующей стороны. Flexbox и grid с логическими свойствами
зеркалятся автоматически; вручную позиционированные элементы — нет. Порядок
цифр внутри чисел никогда не переворачивается, это вместе с остальными
правилами bidi — забота `typography`.

## Упорядочивай по важности

Читатели сканируют сверху вниз, от ведущего к последующему краю. Размещай
контент соответственно:

- Самая важная информация — ближе к верху и ведущему краю. Чем ниже и
  дальше к последующему краю что-то расположено, тем меньше внимания оно
  получает.
- Дай существенной информации место. Никогда не хорони то единственное
  число, ради которого пришёл пользователь, под рядами второстепенных
  деталей — уводи их в свёрнутые секции, табы, детальные экраны.
- Внутри строки идентифицирующий контент ведёт, метаданные и действия
  следуют.

```html
<!-- Хорошо: главный факт первым, деталь второстепенна -->
<div>
  <p class="text-2xl font-semibold">$4,320.00</p>
  <p class="text-sm text-zinc-500">Доступный баланс</p>
</div>

<!-- Плохо: ключевой факт похоронен ниже сгиба карточки -->
<div>
  <p class="text-sm">Счёт 4402 · Открыт 2019 · Стандартный тариф</p>
  <p class="text-sm">Последняя выписка: 30 июня</p>
  <p class="text-sm">Баланс: $4,320.00</p>
</div>
```

С логическими свойствами та же иерархия зеркалится корректно в RTL-локалях.

## Не перегружай точку входа

Первый экран — оглавление, не вся книга. Если всё заметно — не заметно
ничего:

- Одно основное действие на экран. Как цвет усиливает это — забота
  `web-color`/`web-taste`.
- Группируй второстепенные действия в меню, как только их больше двух-трёх.
- Предпочитай короткий экран, ведущий вглубь, длинному, показывающему всё
  сразу на первом уровне.
