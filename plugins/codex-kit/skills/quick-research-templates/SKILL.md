# Быстрые шаблоны исследования

10 небольших генераторов из `pm-skills` (phuryn) — каждый берёт данные
пользователя (сырые данные, транскрипт, описание продукта) и
структурирует вывод по фиксированному шаблону. Не про методологию «как
исследовать» — про то, как оформить результат, когда данные уже есть.
Файлы в `templates/` дословно на английском, атрибуция в начале каждого.

## Какой шаблон когда

| Запрос пользователя | Файл | Вход → выход |
|---|---|---|
| «сделай персоны из этих данных» | `templates/user-personas.md` | Данные исследования → 3 персоны с JTBD, болями, выгодами, неожиданными инсайтами |
| «проанализируй тональность отзывов» | `templates/sentiment-analysis.md` | Отзывы/опросы → сегменты с оценкой тональности, JTBD, инсайтами удовлетворённости |
| «построй customer journey map» | `templates/customer-journey-map.md` | Описание опыта → стадии, точки контакта, эмоции, боли, возможности |
| «найди сегменты рынка» | `templates/market-segments.md` | Продукт/аудитория → 3-5 сегментов с демографией, JTBD, product fit |
| «сегментируй пользователей» | `templates/user-segmentation.md` | Данные фидбека → 3+ сегмента по поведению, JTBD, потребностям |
| «оцени размер рынка» | `templates/market-sizing.md` | Продукт/рынок → TAM/SAM/SOM, top-down и bottom-up |
| «сделай конкурентный анализ» | `templates/competitor-analysis.md` | Список конкурентов → сильные/слабые стороны, возможности дифференциации |
| «напиши скрипт интервью» | `templates/interview-script.md` | Тема исследования → структурированный скрипт (Mom Test: без наводящих вопросов, без питча, фокус на прошлом поведении) |
| «суммаризируй это интервью» | `templates/summarize-interview.md` | Транскрипт → JTBD, сигналы удовлетворённости, action items |
| «построй opportunity solution tree» | `templates/opportunity-solution-tree.md` | Желаемый результат → дерево opportunities → solutions → experiments (Teresa Torres) |

## Как выбирать

Один запрос — один шаблон, если явно не попросили несколько
(«сделай персоны и сегментацию»). Если данных, под которые заточен
шаблон, нет (например, просят TAM/SAM/SOM без данных о рынке) —
сначала попросить их или явно спросить продукт/аудиторию, не
выдумывать цифры произвольно.

`user-personas.md` и `user-segmentation.md` пересекаются — персоны
дают 3 конкретных портрета, сегментация даёт группы по поведенческому
признаку без имён/лиц. Если запрос неясен, что нужно — спросить,
нужны ли именно персоны (для дизайна/копирайтинга) или сегменты (для
приоритизации продукта/маркетинга).

Для методологии первичного исследования (как собирать данные, а не
как оформить готовые) — см. `customer-research` в этом же блоке.
Для полноценной проработанной генерации персоны из JSON-данных со
скриптом — см. `persona-and-journey`.
