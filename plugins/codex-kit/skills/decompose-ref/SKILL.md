# Разбор референса

Скилл разбирает референсный ролик по семи осям монтажа и превращает
разбор в короткий рецепт. Не пересказывает сюжет ролика и не копирует
его содержание - результат это приём, а не копия.

Вызывает `watch` в глубоком режиме. Ритм и склейки видны и в дешёвом
режиме, но ось «Звук» без звуковой дорожки не заполнить.

## Оси разбора

| Ось | Что измеряем |
|---|---|
| Ритм | средняя длина плана в секундах, разброс, где ускоряется |
| Склейки | тип переходов, длительность, привязка к биту |
| Кадр | крупности, движение камеры, композиция |
| Цвет | палитра, контраст, схема грейда |
| Типографика | шрифт, размер, позиция, тайминг появления |
| Звук | музыка, эффекты, где вступают, чем подчёркнуты склейки |
| Структура | хук, развитие, финал, длительность каждой части |

## Выход - два артефакта

1. **Разбор по осям** - таблица выше, заполненная числами и фактами
   конкретного ролика.
2. **Рецепт** - короткая инструкция по приёму, без привязки к сюжету
   референса. Пригодна как задание на стиль для скилла `script` блока
   `video-pipeline`.

## Жёсткие правила

- Числа обязательны. «Динамичный монтаж» без секунд не принимается,
  нужна конкретная длина плана.
- Содержание референса не копируется, копируется только приём монтажа.
- Ролик разобран только дешёвым режимом `watch` значит ось «Звук»
  помечается как недоступная. Не выдумывать музыку и эффекты по кадрам.

## Соседние скиллы

Зовёт `watch` (этот же блок) в глубоком режиме до начала разбора.
Рецепт на выходе идёт в `script` блока `video-pipeline` как задание
на стиль.

---

*Источник: собственный скилл блока `video-watch`, поверх `watch` и
Gemini Files API - чужого инструмента под разбор по осям нет.*
