# Исполнение программы

5 инструментов из `Owl-Listener/ux-pgm-skills`, обобщены от UX-
программы до любого проекта/программы. Файлы в `templates/` дословно
на английском, атрибуция в начале каждого.

## Какой инструмент когда

| Запрос пользователя | Файл | Что даёт |
|---|---|---|
| «разбей roadmap на исполняемый план» | `templates/delivery-plan.md` | Milestone → задачи ≤1 недели, один владелец на задачу, definition of done, порядок по зависимостям |
| «разбери блокеры» | `templates/blocker-triage.md` | Что заблокировано / чем / кто может разблокировать / severity / возраст блокера — ежедневный 10-минутный скан |
| «веди реестр рисков» | `templates/risk-register.md` | Likelihood × impact → severity, владелец, реакция (avoid/mitigate/transfer/accept), триггер |
| «проведи go/no-go ревью» | `templates/launch-readiness.md` | Чек-лист по доменам (дизайн/доступность/контент/инженерия/поддержка/метрики) → явное go / no-go / conditional-go |
| «сделай ретроспективу программы» | `templates/retrospective.md` | Blameless разбор всего таймлайна → 2-3 owned и датированных действия, перенос в следующую программу |

## Как выбирать

`delivery-plan` — точка входа после того, как roadmap готов
(`program-planning/program-roadmap`). `blocker-triage` и `risk-
register` — параллельно на всём протяжении исполнения, не разово.
`launch-readiness` — перед конкретной поставкой/релизом.
`retrospective` — после завершения программы или крупной фазы.

**`retrospective` здесь — altitude программы**, не спринта и не общего
процесса команды. Не путать с `product-execution/sprint-cycle/retro`
(один спринт, 2-3 action item, формат Start/Stop/Continue) — тот
скилл про короткий цикл одной команды, этот — про программу/квартал в
целом с несколькими командами. Третий altitude, ретро самого процесса
работы команды (не одной программы) — `process-design/process-
retrospective`, кандидат в соседний блок. Не ставить два ретро-скилла
на одну и ту же сессию без явного уточнения масштаба.

`risk-register` (программные риски) отличается от `risk-register`-
раздела в `product-execution/risk-review` (методы стресс-теста плана
до старта, не живой реестр во время исполнения) — разные стадии,
не дубль.
