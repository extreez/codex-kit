# llms-txt

`llms.txt` — не официальный веб-стандарт (в отличие от `robots.txt`), а
предложенная конвенция, которую часть AI-платформ уже читает. Файл — карта
контента сайта в Markdown, оптимизированная для потребления моделью, а не
для рендера в браузере.

## Точный формат

Файл — обычный Markdown по строгой структуре:

```markdown
# Название сайта/продукта

> Одна-две строки: что это за сайт/продукт, для кого, чем полезен.
> Эта часть — цитата (blockquote), не обычный абзац.

Необязательный вводный абзац с дополнительным контекстом, без строгой
структуры — не обязателен, если краткого описания в цитате достаточно.

## Раздел 1 (например, Documentation)

- [Название страницы](https://site.com/page.md): краткое описание, зачем
  переходить именно сюда
- [Название другой страницы](https://site.com/other.md): краткое описание

## Раздел 2 (например, Guides)

- [Название](https://site.com/guide.md): описание

## Optional

- [Второстепенная страница](https://site.com/misc.md): для материалов,
  которые не критичны для основного понимания сайта
```

Правила формата:
- **H1** — один, название сайта/продукта.
- **Цитата сразу после H1** — краткое описание в формате `>` (blockquote),
  не обычный текст. Это единственный обязательный вводный элемент.
- **H2-разделы** — логическая группировка страниц (Documentation, Guides,
  API Reference, Blog и т.п.), название разделов свободное, под структуру
  конкретного сайта.
- **Ссылки — на `.md`-версии страниц**, не на обычный HTML URL. Если у
  сайта нет отдельных `.md`-версий, ссылка на обычную страницу допустима,
  но `.md` предпочтительнее — модель не тратит бюджет на разбор HTML/CSS/
  JS вокруг текста.
- **Каждая ссылка с кратким описанием** после двоеточия — не голый список
  URL, модель должна понимать по одной строке, стоит ли переходить.
- **Раздел `Optional`** — единственное зарезервированное имя раздела
  (не переименовывать), для материалов, без которых можно понять сайт.

## `llms.txt` vs `llms-full.txt`

- **`llms.txt`** — карта ссылок с краткими описаниями (формат выше). Для
  моделей, которые сами переходят по ссылкам и читают отдельные `.md`.
- **`llms-full.txt`** — весь контент сайта (или его основной части) в
  одном файле, конкатенированный Markdown. Для моделей/агентов, которые
  за один заход читают весь контекст без перехода по ссылкам. Больше по
  размеру, но не требует follow-up запросов.

Оба файла — в корне сайта: `/llms.txt`, `/llms-full.txt`.

## Валидация перед публикацией

1. **H1 и цитата на месте**, цитата действительно оформлена как blockquote
   (`>`), не просто первый абзац.
2. **Все ссылки рабочие** — каждая ссылка в файле отдаёт 200 (или ведёт на
   существующую `.md`-версию).
3. **Нет дублей ссылок** между разделами.
4. **Разделы логичны** — H2 группирует тематически близкие страницы, не
   случайный порядок публикации.
5. **Размер `llms-full.txt` разумен** — если сайт большой, полная
   конкатенация может не влезать в контекст модели; для больших сайтов
   `llms-full.txt` может ограничиваться самым важным разделом с явной
   пометкой в `llms.txt`, что это не весь контент.
6. **Файл актуален** — план обновления при добавлении новых ключевых
   страниц (иначе файл быстро расходится с реальной структурой сайта и
   становится источником устаревших ссылок).

## Карта поддержки движками

**Сверить на момент использования — эта карта могла устареть.** На момент
источника (RU-статья, vc.ru):

| Движок | Поддержка |
|---|---|
| Claude (Anthropic) | использует явно |
| Perplexity | использует явно |
| OpenAI/ChatGPT | собирает через краулер (`GPTBot`/`OAI-SearchBot`), не подтверждает прямое использование содержимого `llms.txt` как приоритетного источника |
| Google | не поддерживает `llms.txt` как отдельную конвенцию (индексирует сайт обычным способом) |
| Яндекс | не поддерживает |

Источник отмечает кейс роста трафика из AI-чатов на ~23% после внедрения
`llms.txt` — единичный пример, не гарантированный результат, приводится
как ориентир, не как обещание.

## Отчёт/результат

Файлы `llms.txt` (и опционально `llms-full.txt`) в корне сайта, прошедшие
валидацию по пунктам выше. Готово — когда все ссылки в файле отдают 200 и
структура (H1 → цитата → H2-разделы) соблюдена.

## Смежные блоки

`geo-content` — контент, на который ссылается `llms.txt`, готовится там
(атомизация, `.md`-версии страниц как отдельная сущность). `geo-optimize` —
наличие и валидность `llms.txt`/`llms-full.txt` входит в citability/
technical сигналы composite score.

`.md`-версии страниц генерируются из CMS, а не руками - см.
`library/seo-content-cms-tool/README.md`.
