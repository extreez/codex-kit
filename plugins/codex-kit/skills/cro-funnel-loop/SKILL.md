# cro-funnel-loop

Автоматизирует `cro-funnel` двумя механизмами: гейт на выходе из сессии,
цикл до нуля High-находок. По образцу `seo-loop`, адаптировано под
воронку конверсии.

## 1. Stop-гейт (хук, уже активен блоком)

Хук `stop-gate.js` не даёт закончить сессию, если менялись файлы
регистрации/онбординга/paywall/попапа/формы (по ключевым словам в пути:
`signup`, `onboard`, `checkout`, `paywall`, `popup`, `pricing`, `form`),
а `/cro-funnel` по этой зоне не прогнан. Напоминает один раз, дальше
решение за тобой — эвристика по имени файла грубая (как у `seo-loop`),
не строгая проверка, ложные срабатывания возможны на файлах со случайным
совпадением ключа в пути.

## 2. Цикл диагностика-фикс-перепроверка до нуля High

Крутит проход, пока критерий не выполнен. Критерий проверяемый: **ноль
находок Priority=High** в последнем бэклоге `/cro-funnel`.

Один проход:
1. `/cro-funnel` (вся воронка при первом проходе, дальше — только
   изменённая зона).
2. Каждая находка High → фикс (реальное изменение флоу, не косметика —
   подтверждение владельца перед правкой логики регистрации/оплаты).
3. Повторный обход изменённой зоны.
4. Снова `/cro-funnel` по этой зоне. Ноль High — стоп. Иначе новый
   проход.

Собирается через `/goal` и/или `/loop` (скилл `loop-build`). Условие
остановки — команда, а не ощущение: перечитать свежий вывод `/cro-funnel`
и посчитать находки Priority=High, должно быть 0.

Модель, эффорт и количество субагентов под каждый шаг спрашиваются при
запуске (правило). Перед стартом покажи схему пользователю.

Medium/Low находки цикл не гоняет до нуля — не критично для конверсии
в моменте, решение по ним за владельцем проекта отдельно.

## Границы

- Цикл не переписывает бизнес-логику оплаты/регистрации без
  подтверждения — только явно согласованные фиксы из бэклога.
- Гейт только напоминает, не блокирует навсегда — обходится осознанно.
- Не путать с `content-loop` (цикл контентного конвейера, другая
  задача) и `paid-ads-loop` (цикл рекламных тестов).
