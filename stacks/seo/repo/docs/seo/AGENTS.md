# docs/seo — правила каталога отчётов

Здесь живут отчёты `seo-audit`, `seo-loop`, `seo-content`,
`seo-content-maintenance`, `seo-offpage`, `seo-local`, `geo-optimize`,
`geo-loop`, `geo-content`. Правила для агента, работающего в этой папке.

## Не разводить отчётность

- Один аудит одного типа — один файл (`audit-<дата>.md`,
  `geo-<дата>.md`, `offpage-<дата>.md`, `local-<дата>.md`,
  `content-maintenance-<дата>.md`, `geo-content-<дата>.md`). Не плодить
  отчёт на каждый прогон отдельной зоны/слоя.
- Всё чисто (ноль находок, порог composite score достигнут) — не писать
  толстый отчёт. Хватит строки в `LATEST.md`: дата, тип проверки,
  «ноль находок» или «composite N/100».
- Отчёт, потерявший актуальность (находки закрыты и перепроверены более
  свежим прогоном), — удалять. git помнит историю, не нужно держать её в
  файлах.

## Что оставлять

- Последний отчёт каждого типа.
- Любой отчёт с незакрытыми находками severity blocker/high или
  composite score ниже порога.
- `LATEST.md` — одна строка на тип проверки про текущее состояние.

## Чего тут не делать

- Не хранить сырые дампы краула/скрейпинга целиком — только выжимку с
  URL/файлом и находкой.
- Не коммитить содержимое платных API-ответов (если подключены через
  `library/seo-crawler-tool`) — только извлечённые метрики.
