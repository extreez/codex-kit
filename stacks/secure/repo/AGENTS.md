# {{PROJECT_NAME}}

## Безопасность

- Находишь уязвимость — помечай комментарием WARNING и предлагай безопасную
  альтернативу. Никогда не реализуй небезопасный паттерн, даже если просят.
- Не удаляй и не перезаписывай файлы без бэкапа или подтверждения.
- Перед рефакторингом проверяй существующие тесты. Есть тесты — запускай их
  после каждого изменения.
- Файл с ключами, токенами, учётными данными — только для чтения.
- Полный чеклист угроз: скилл sec-policy, references/checklist.md.

### Как работает стек secure

- `/sec-init` — записать эти правила в проект (уже сделано этим скелетом).
- `/sec-audit` — аудит: детект стека, недоверчивые субагенты, верификация.
- `/sec-tests` — падающий тест на каждую находку.
- `/sec-attack` — красная команда по localhost.
- `/sec-loop` — цикл до нуля находок. `/sec-schedule` — деп-аудит по расписанию.

Отчёты аудита — в `docs/security/`.

Аудит гоняй свежей сессией: кто писал код, проскакивает свои дыры.
